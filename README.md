# MyAthanor

個人用リソース・アイデア管理ツール（MVP）。

日々の思いつき（**アイデア**）と出来事（**ログ**）を記録し、そこから
**ミッション**を切り出して、消費する **タイム／ウォレット** を見積もる。
ミッションを完了するとログが自動生成され、見積もりが消費予定から消費済みへ移る。
ホームの試験管で「消費済み・消費予定・残量」を常時把握できる。

## 起動

```bash
npm install
npm start          # http://0.0.0.0:3000
```

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DB_PATH` | `data/myathanor.db` | SQLite ファイルの場所 |

`npm run dev` はファイル変更で自動再起動する。

DB は初回起動時に自動作成される。バックアップは `data/` をコピーすれば足りる。

### スマホから使う

`0.0.0.0` で待ち受けているので、ホストPCの Tailscale アドレスに
`http://<tailscale-name>:3000` でアクセスする。認証は持たない
（要件どおり Tailscale のネットワーク層制限のみを前提とする）ので、
**Tailnet の外に公開しないこと**。

### 常時起動させる

ノートPC で常駐させる場合の systemd user unit の例:

```ini
# ~/.config/systemd/user/myathanor.service
[Service]
WorkingDirectory=/path/to/MyAthanor
ExecStart=/usr/bin/node --no-warnings=ExperimentalWarning server.js
Restart=always

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable --now myathanor
loginctl enable-linger "$USER"   # ログアウト後も動かす
```

## 構成

```
server.js          Express アプリ（API + 静的配信 + SPA フォールバック）
src/db.js          SQLite 接続とスキーマ
src/period.js      週（月曜始まり）／月の集計期間と日付ユーティリティ
src/store.js       データアクセスと状態遷移
src/routes.js      REST API
public/app.js      Web UI（ビルド不要の ES モジュール）
public/icons.js    ドット絵アイコン（16x16 のグリッドから SVG を生成）
public/styles.css  見た目
```

依存は Express のみ。SQLite は Node 22 標準の `node:sqlite` を使うため
ネイティブビルドは発生しない（Node 22.5 以上が必要）。

## 単位の扱い

- **タイム**: DB には**分**の整数で保持し、UI は**時間**で表示・入力する
- **ウォレット**: **円**の整数

## リソースの集計

| | 集計対象 | 期間 |
|---|---|---|
| 消費済み | `log.time_spent` / `log.money_spent` の合計 | タイムは今週（月曜始まり）、ウォレットは当月 |
| 消費予定 | 進行中ミッションの見積もりの合計 | 期間で絞らない（これからやることのため） |
| 残量 | 可処分 − 消費済み − 消費予定 | ＝「進行中ミッションを全て完了した場合の残量」 |

期間の境界はサーバのローカルタイムゾーンで判定する。

## 可処分リソースの管理

可処分量は **タイムが週単位（月曜始まり）、ウォレットが月単位** で管理する。
設定画面は2段構えになっている。

- **既定値**: 個別設定を持たない期間すべてに適用される
- **期間ごとの個別設定**: 特定の週／月だけ値を変える。`既定へ` で個別設定を消すと
  その期間は既定値に戻る

個別設定は `budget` テーブルに `(kind, period_key, amount)` として持つ。
`period_key` は週なら月曜日の日付 `YYYY-MM-DD`、月なら `YYYY-MM`。
既定値を後から変えても、個別設定を入れた期間の値は動かない。

設定画面の一覧には直近の期間に加えて、範囲外でも個別設定を持つ期間が必ず出る。
`さらに過去` でさらに遡れる。各期間には実際の消費済み量が並ぶので、
見積もりの妥当性をその場で確認できる。

## 定期イベント

定期的に起こる出来事を登録しておくと、**開催日が来た回は自動でログになる**。
例外があるときだけ、その回を触ればよい。

- 繰り返しは **毎日／毎週（曜日指定）／毎月（日付指定）**。
  月末に無い日付（2月31日など）はその月の末日に寄せる
- 開催日を過ぎた回は自動でログ（消費済み）になる。
  まだ来ていない回は、その期間内であれば試験管の**消費予定**に乗る
- その回だけ値を変える／スキップする、が個別にできる。
  記録済みの回を後から直すとログにも反映され、スキップすればログは取り消される
- 定義を消しても、生成済みのログは記録として残る

同期は API リクエストのたびに走るが、その日ぶんが済んでいれば実質何もしない。
開始日を大きく過去にした場合の遡り生成は366日ぶんで打ち切る。

個別の回は `occurrence` テーブルに、定義と違う回だけ行を持つ。
値が NULL の項目は定義を継承するので、定義側を直せば個別指定していない回は追随する。

## タグ

アイデアとログにタグを付けられる。ストリームは **時系列** と **タグ別グループ** を
切り替えられ、時系列のときはタグで絞り込める。

- タグは付けるときに名前で指定する。無い名前はその場で作られる
- 前後の空白と連続空白は詰めて正規化するので、` 音楽 ` と `音楽` は同じタグになる
- 複数タグが付いた項目は、タグ別表示ではそれぞれの束に出る。タグなしは「未分類」に集まる
- 名前の変更と削除は 設定 → タグの整理 から。削除してもタグが外れるだけで項目は残る

要件のフェーズ2は「AI提案＋手動修正」だが、提案する側（ローカルLLM）はフェーズ3の
範囲なのでまだ無い。いまは手動のみで、データの持ち方は提案を後から足せる形にしてある。

## アイデアの温度

アイデアには温度（K表記）がある。**273K（0℃）を常温＝基準**とし、
熱を入れてから触らずにいると基準へ向かって冷めていく。

- スライダーで 273K〜373K を設定する。設定すると冷却の起点が今にリセットされる
- 冷却は半減期方式。半減期ぶんの日数が経つごとに、273K からの差が半分になる
  （既定30日。半減期30日・370Kなら 30日後に322K、60日後に297K、180日後に275K）
- 半減期は 設定 → アイデアの冷却 で変えられる。**0 にすると冷めない**
- 温度は保存された値そのものではなく、読むたびに経過時間から計算する。
  つまり冷却のためのバッチ処理は無く、半減期を変えれば過去のアイデアの温度も即座に変わる

熱さは 沸騰（350K〜）／熱い（320K〜）／ぬるい（295K〜）／冷めかけ（276K〜）／凍結（〜275K）で
色とアイコンが変わる。凍結だけ炎ではなく霜の結晶になる。

なお、ミッションを切り出すなどの操作で自動的に熱が戻ることはしていない。
温度を動かすのは明示的な操作だけなので、冷めていることに気づいたら自分で入れ直す。

## ミッションの期日

ミッションには **いつから（開始日）** と **いつまで（期限）** を任意で付けられる。
どちらも `YYYY-MM-DD` のローカル日付で、片方だけでもよい。

- ミッション画面は **期限順** と **新しい順** を切り替えられる。既定は期限順
- 期限順は「期限の近いものから並べ、期限の無いものは末尾」。
  末尾に何件あるかは一覧の上に出す
- 進行中のものだけ、残り日数をバッジで出す。
  超過（赤）／今日まで（金）／あと3日以内（金）／あとN日（淡色）／N日後に開始
- 日付はカードの「日付を決める」を開けばその場で変えられる。空にすれば外れる
- 期限が開始日より前だと 400 を返す

**大釜にも同じ日付を持たせられる。素材は自分の期限が無ければ大釜の期限を引き継ぐ**
ので、大きなイベントには大釜側に一度だけ日付を振れば足りる。
素材に自分の期限を入れればそちらが優先され、大釜の日付を変えれば引き継いでいる
素材だけが追随する。並び替えもこの実効の期限で行う。

ホームの進行中ミッションと、アイデア／ログ詳細のミッション一覧も期限順で並ぶ。

## 大釜（ミッションのTODOリスト）

ひとつの大きなイベントに必要なミッションを、**素材**としてまとめて並べる器。
大釜はアイデア／ログにぶら下がり、素材はその大釜に入ったミッションになる。

- 素材は1行1つのテキストでまとめて投入できる
- 素材が1つ以上あって、**断念を除く全部が完了**すると錬成が終わる。
  逆に完了を取り消したり素材を足したりすると、錬成中に戻る
- 断念した素材は「要らなくなったもの」として必要数から外れる
- 大釜を捨てても素材は消えない。単独のミッションに戻るだけ

素材も普通のミッションなので、完了すればログが生成され、リソースの集計も
今までどおり効く。大釜が増やすのは「まとめて並べて、そろったかを見る」という
見え方だけで、リソースの数え方は変えていない。

## ダンジョン

たまっていく情報を**道**として地図にする画面。

| 地図の要素 | 中身 |
|---|---|
| 部屋 | アイデア（賢者の石）／ログ（足跡） |
| 通路 | ミッション。実線＝通った道、破線＝掘削中、点線＝崩落（断念） |
| 行き止まり | 完了していない通路の先。掘削中か崩落 |
| 大釜 | 同じ器に入った素材の束。1つに畳んで「3/4 錬成中」と出す |
| 宝箱 | レガシー |
| 縦方向 | 深さ。子は必ず親より後に生まれるので、下へ行くほど後の時間 |
| 横方向 | 枝分かれ |
| 区画 | タグ |

- 入口はアイデア全部と、ミッション由来ではないログ
- **道のどこかに付いたタグ**で区画に振り分ける。入口だけでなく途中のログに
  付けたタグでも辿れる。タグが1つも無い道は「未踏」に集まる
- 大釜は素材ごとにレーンを取らない。素材の先にさらに道が続いているものだけ、
  大釜から枝として伸ばす。畳まないと横に広がりすぎて携帯の画面に収まらない
- 地図が画面より広いときは区画の中だけで横スクロールする
- 部屋をタップするとその詳細へ飛ぶ

**レガシー**は、ログと**完了した**ミッションにつけられる印で、地図の上では宝箱になる。
進行中・断念のミッションには付けられない（409 を返す）。
画面下の「宝物庫」に集まり、「宝箱のある道」でその印を含む道だけに絞り込める。

| メソッド | パス | 内容 |
|---|---|---|
| `GET` | `/api/stream?type=all\|idea\|log&tag=` | アイデアとログの時系列（タグ・温度つき） |

| `POST` | `/api/cauldrons/:id/materials` | 素材をまとめて投入 |
| `GET` `POST` | `/api/tags` | タグの一覧（件数つき）／作成 |
| `PATCH` `DELETE` | `/api/tags/:id` | タグの名前変更／削除 |

## MVP の範囲

要件定義の 6.1〜6.5 を実装している。

- ストリーム（種別フィルタ、＋からの追加）
- アイデア／ログ詳細（タイトル編集、ミッション追加、紐づくミッション一覧）
- ミッション（ステータス別フィルタ、元エントリへのリンク、完了／断念）
- ホーム（タイム／ウォレットの試験管、全完了時の残量）
- 設定（週あたりの可処分タイム、月あたりの可処分ウォレット）

要件に無いが操作の行き止まりを避けるために足したもの:

- ログ詳細での実消費（タイム／ウォレット）の入力 — 「ログ直接入力で確定」する経路
- 断念したミッションを進行中に戻す操作
- 可処分量の期間ごとの個別設定（前掲）。要件 6.5 は単一の値だけだが、
  週・月ごとに実態が変わるため既定値からの上書きを持てるようにした
- 定期イベント、ダンジョン、レガシー、大釜（前掲）

フェーズ2のうち、タグとアイデアの温度は実装済み（前掲）。
タグのAI提案、ミッションの「未着手」「保留」、週カレンダーによる可処分時間の
範囲選択はまだ。

## 見た目

中世ファンタジー寄り。緑（薬草）・茶（革と木）・黄金（金貨）を基調にしている。

- 絵情報はすべて**ドット絵**。`public/icons.js` に 16x16 のグリッドを文字で持ち、
  横に連続する同色をまとめて `<rect>` に変換する。外部画像は使わない
- アイコンは **アイデア＝賢者の石、ログ（出来事）＝歩いた足跡、ミッション＝羊皮紙**。
  ほかに定期イベント＝砂時計、設定＝鍵、レガシー＝宝箱、ダンジョン＝石の門、
  アイデアの温度＝炎（冷めきると霜の結晶）、大釜＝鍋。
  炎は熱さに応じて配色だけ差し替える
- リソースは**2色の試験管**。下から順に、消費済み（薬草色）と消費予定（琥珀・斜線）。
  残量は空のガラスとして残り、可処分を超えると管の縁が赤くなる
- 書体は和文を先頭に置く。欧文書体を先に書くと欧文だけ西洋の書体になり、
  和文はシステム任せになって翻訳物のような字面になるため。
  iOS/macOS はヒラギノ、Windows は游書体／BIZ UD、Android は Noto（源ノ）が当たる。
  末尾の IPA は Linux 向けの保険で、総称 `serif` / `sans-serif` に落ちて
  中国語の書体が当たるのを防ぐためのもの
- 数値は要件どおり等幅。欧文の等幅を先に書き、仮名・漢字だけ和文書体に落とす
- ボタンは影も光沢も付けず、面と1pxの枠だけで組む

タブは要件の3つに **ダンジョン**を加えて4つにした。
つながりを見る画面は他から辿らせるには主役すぎるため。
