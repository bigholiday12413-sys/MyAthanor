# MyAthanor

個人用リソース・アイデア管理ツール（MVP）。

**日々のやることを錬金術に見立てる。**タイムとウォレットという2つのリソースを
注ぎ込んで成果物を作る、という筋で言葉と絵を揃えてある。
日々のやることは**フラスコ**（プロセス）、意思や思いつきは**宝石や金属**
（アイデア・インゴット）として持つ。

日々の思いつき（**アイデア**）と出来事（**ログ**）を記録し、そこから
**プロセス**を切り出して、消費する **タイム／ウォレット** を見積もる。
プロセスを完了するとログが自動生成され、見積もりが消費予定から消費済みへ移る。
ホームの試験管で「消費済み・消費予定・残量」を常時把握できる。

## 起動

```bash
npm install
npm start          # http://0.0.0.0:3000
```

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DB_PATH` | `data/myathanor.db` | SQLite ファイルの場所 |

`npm run dev` はファイル変更で自動再起動する。

DB は初回起動時に自動作成される。バックアップは `data/` をコピーすれば足りる。

### スマホから使う

`0.0.0.0` で待ち受けているので、ホストPCの Tailscale アドレスに
`http://<tailscale-name>:3000` でアクセスする。認証は持たない
（要件どおり Tailscale のネットワーク層制限のみを前提とする）ので、
**Tailnet の外に公開しないこと**。

### 見本版（GitHub Pages）

サーバを立てずに、URL を開くだけで触れる見本を `main` への push ごとに出す。
スマホから見た目と操作感を確かめるためのもの。

```
https://bigholiday12413-sys.github.io/MyAthanor/
```

**初回だけリポジトリ側の設定が要る。**
Settings → Pages → Source を **GitHub Actions** にしてから、
Actions → Pages → Run workflow で一度流す。

これを workflow 側から自動でやることはできない。サイトの作成はリポジトリの
**管理権限**が要り、workflow の `GITHUB_TOKEN` には無いため
（`permissions: pages: write` は配信までしか届かない）。
`configure-pages` に `enablement: true` を渡すと
`Resource not accessible by integration` で落ちる。
`main` に入る前に見たいときは、Actions → Pages → Run workflow でブランチを選べば出る。

**出るのは見本版だけで、持ち主のデータは1件も載らない。**
見本版は `demo/seed.js` の作り物をブラウザの中の SQLite に入れて動いていて、
`data/myathanor.db` は組み立てにも配信にも関わらない。

仕組みは「本体のコードをそのまま持っていき、DB の1ファイルだけ差し替える」。

- `src/store.js` は `node:sqlite` を直接は触らず、`./db.js` の `db` を使っているだけ。
  そこへ WASM の SQLite（sql.js）を同じ形でかぶせた `db.js` を置くと、
  **store.js も routes.js も1行も変えずにブラウザで動く**
- `/api` への fetch を横取りして `src/routes.js` に渡す。express の `Router` は
  使っている範囲だけ真似たものに差し替える（`demo/express.js`）
- つまり**見本版と本体でロジックが別物にならない**。画面・集計・状態遷移は同じものが走る
- データは端末の localStorage に残り、初回だけ見本を入れる。「最初に戻す」で消せる
- スキーマは `src/schema.js` に切り出して両方から使う。片方だけ列が増えることがない
- **`index.html` も本体のものから組み立てる。**写しを持つと、タブの名前を変えたときに
  片方だけ古いまま残る（実際に「ミッション／ダンジョン」のまま出ていた）。
  違うのは見本である断りと、読み込む部品の3点だけなので、`demo/banner.html` を
  差し込み、更新の知らせとサービスワーカーを外して作る。
  組み立ての最後に、消したはずのものが残っていないか・入るはずのものが入ったかを
  文字列で当たっている

```bash
npm run build:demo   # site/ に組み立てる
```

見本の日付は「今」から逆算して入れている。置いた日付を焼き込むと、
時間が経つほど古びて、期限や試験管の見え方が変わってしまうため。

### 常時起動させる

```ini
ExecStart=/usr/bin/node --no-warnings=ExperimentalWarning server.js

```

```bash

loginctl enable-linger "$USER"   # ログアウト後も動かす
```

```
src/db.js          SQLite 接続

public/app.js      Web UI（ビルド不要の ES モジュール）
```

## 単位の扱い

- **タイム**: DB には**分**の整数で保持し、UI は**時間**で表示・入力する
- **ウォレット**: **円**の整数

## リソースの集計

**タイムもウォレットも1週間（月曜始まり）**を1期間として、その期間の中だけを見る。
ウォレットも週に揃えたのは、2つの刻みを頭の中で行き来しなくて済ませるため。

| | 集計対象 | 期間の絞り方 |
|---|---|---|
| 全体 | 入ってくる量 − 固定費 | その期間ぶん |
| 消費済み | ログの `time_spent` / `money_spent` | その期間に起きたログ |
| 消費予定（プロセス） | 進行中プロセスの見積もり | **期限がその期間の終わりまでに来るもの**。期限切れも含む |
| 残量 | 全体 − 消費済み − 消費予定 | ＝「その期間ぶんをやり切ったときの残り」 |

**循環から来るものは、消費済みにも消費予定にも乗らない。**固定費として先に
引いてあるので、そこで数えるとひとつの出費を二度引くことになる。

期限を持たないプロセスは試験管に乗らない。**代わりにホームへ別枠で出す**ので、
乗っていないことに気づける（見積もりが 0 のときは出さない）。
種は期限を持たないが、固定費として乗っているのでこの別枠には出さない。
期限切れのプロセスを今期に含めるのは、過ぎていても払う／やるぶんだからで、
視界から消すと危ないため。

期間の境界はサーバのローカルタイムゾーンで判定する。

### 固定費 — 繰り返すものは月の収入と同じ扱いにする

**繰り返すプロセスは「決まって出ていくもの」なので、月の収入と同じ側で相殺する。**
毎回どうするか決めるものではないから、週ごとの消費予定として立てない。

```
その週に使える量 ＝ 入ってくる量 − 固定費の週割り
                      ↑報酬÷4 または週のタイム
```

- 種の見積もりは1回ぶんなので、**1週あたりは `見積 × 7 ÷ 周期`**。
  周期30日のものは月ぶんがちょうど戻る
- **タイムもウォレットも同じ扱い。**毎週2時間の掃除は、時間の固定費に他ならない
- **個別設定の週からも引く。**可処分の定義をひとつに保つため。設定画面の入力欄が
  受け取るのは「入ってくる量」で、固定費を引いた後の数はその下に出す
- 固定費が入ってくる量を超えると全体が負になる。赤で出して、そのままにする。
  丸めて隠すと赤字に気づけない

週ごとに立てると、家賃の来た週だけ真っ赤になって、他の週が実態より豊かに見える。
均せば、どの週も「固定費を払ったあとに手元に残るぶん」を出す。
これは要件に無いが、月の収入と月の固定費を別々に扱うと、
週で暮らすという前提そのものが成り立たないため入れた。

### 貯金のように「使わずに取っておく」を扱う

欲しいものをアイデアとして立て、その貯金を**期限つきのプロセス**にすると、
給料日までのあいだ試験管に琥珀色で立ち続ける。残量＝実際に使ってよい額になるので、
残量を見て暮らすだけで貯金分が守られる。貯金したらプロセスを完了すれば、
消費済みへ移って確定する。

毎月続くものは**繰り返すプロセス**にする。周期を入れておけば固定費として
先に引かれるので、残量を見て暮らすだけで済む（前掲）。

## ホームの並び

上から**週の紙 → リソース → 調合棚**。数を並べる枠（現況）は置かない。

**週の紙**は7枚を月曜から並べたもので、終わった曜日から順に印が入る。
今日の紙にはまだ印を入れない。終わっていないから。
曜日の文字は出さない。左から月曜と決まっていて、印の数で何日目かが読める。
読み上げには要るので、曜日名は `aria-label` にだけ残す。
数字を読む前に「いま週のどこに居るか」が目に入るようにするためのもので、
タイムもウォレットも週で見るようになったので置いた。

進行中のプロセスの一覧はホームに置かない。プロセスのタブに同じものがあり、
1画面ずつめくる作りでは、同じ札を2か所に出すと送る回数が増えるだけになる。

**調合棚**は、**今日から7日先まで**に期限が来るプロセスを丸底フラスコとして並べたもの。
暦の週ではなく今日を起点にするのは、週の後半になるほど棚が短くなるのを避けるため。
期限の早い順で、中身の高さが残り日数。期限が近いほど減っていて、過ぎたものは
口から吹きこぼれて赤くなる。上の試験管と同じガラスの一家にしてあるので、
同じ工房の棚に見える。日数は書かない（液の高さで読める）。

- **満タンにはしない（最大8割）。**口まで詰まっていると、揺らせば溢れるように
  見えて落ち着かない。実際の調合も口いっぱいには入れない
- 液は2色。地を暗くして、水面と左肩に明るいほうを1段だけ置く。
  全部明るいと平たく見える
- **数は棚のフラスコの数がそのまま。**別に数字を書かない
- **先のプロセスは並べない。**期限を短く切るのは持ち主の運用で、
  遠い先まで並べると、いま見るべきものが埋もれる
- **繰り返しから生えたフラスコには循環の印**を重ねる。棚を見ただけで
  「これは勝手に来たぶん」と分かる。別枠に吊るしたりはしない
- **棚番**（白い布をかぶり、黒い魔女帽を斜めにかぶった2等身のもの）が、
  フラスコと同じ段を歩く。大きさもフラスコに揃えてあるので背丈が並ぶ。
  1歩に3秒。端まで行くと**10秒ほど姿を消し**、向きを変えて戻ってくる。
  止まる場所はフラスコの位置とちょうど重なる
  - 歩く柄を3枚持ち、1歩ごとに次の柄へ移る。輪郭は変えず、布の影と裾の位置を
    1ドットずらすだけ。輪郭まで動かすと、この大きさでは別人に見える
  - 道筋は本数で変わるので `@keyframes` はその場で組む。各keyframe に
    `step-end` を付けて中割りを止める。中割りするとドットが半端な位置に来る
  - 動かすのは `transform` と `opacity` だけなので合成で済み、フラスコが
    何本あっても値段は変わらない（10秒あたりの仕事量は、動かさない場合と
    同じ 1ms 前後）。`prefers-reduced-motion` では左端に立ったまま止まる
  - いつも横向き。布は前だけ開けて、前髪と鼻と顎の輪郭だけを出す。目は描かない
  - 裾に向けて丸めない。丸めると雪だるまになるので、真っ直ぐ落として裾で切り、
    後ろへ布を引きずらせる
  - 帽子はつばから立ち上げて途中で折り、先端を後頭部の側へ垂らす。
    真っ直ぐ尖らせると硬い三角にしか見えない
  - 帽子のぶん縦に伸びるので、この絵だけ 16x20 で持つ（他は 16x16）

**金庫**は枠を持たず、ウォレットの試験管の足もとに置く。
タイム側は貯まるものが無いので空けてあるが、枠は残す。
片方だけ丈が変わると、2本の管の目盛りがずれて見えるため。
差し引きには名前を書かない。上に引いた線と、緑と赤の使い分けで読める。

**ユーズド**（今週のウォレットが何に出ていったか）はホームに置かず、
ウォレットの試験管の見出しから飛ぶ。ホームは「いま週のどこに居るか」だけでよく、
内訳は見に行くもの。各行からはストリームのその絞り込みへ飛べる。

## 使えるリソースの管理

使える量は **タイムもウォレットも週単位（月曜始まり）** で管理する。
設定画面は2段構えになっている。

- **既定値**: 個別設定を持たない期間すべてに適用される
- **期間ごとの個別設定**: 特定の週だけ値を変える。`既定へ` で個別設定を消すと
  その期間は既定値に戻る

**ウォレットの既定値だけは、月あたりの「報酬」として持つ。**
入ってくる額は月で決まっているのに、使うのは週で見たいため。
設定に入れた報酬を **4で割った額**が、その週の既定値になる（`weeklyShare`）。
月を4週として割り切る。実際の週数（4.3週）で割らないのは、
端数の出ない数のほうが、暮らしの中で見当が付けやすいから。

個別設定は `budget` テーブルに `(kind, period_key, amount)` として持つ。
`period_key` はどちらも週の月曜日 `YYYY-MM-DD`。
既定値を後から変えても、個別設定を入れた期間の値は動かない。
月単位だった頃の `YYYY-MM` の行は読めなくなるが、消してはいない。
週のキーとして解釈できないものは黙って飛ばす。

設定画面の一覧には直近の期間に加えて、範囲外でも個別設定を持つ期間が必ず出る。
`さらに過去` でさらに遡れる。各期間には実際の消費済み量が並ぶので、
見積もりの妥当性をその場で確認できる。

## インゴット

「したいこと」ではなく、**良いと思った物事・考え方**を持っておく場所。
ホーム右上の原石のアイコンから開く。

- インゴットは題と本文（任意）を持つ。**ストリームには出ない**。
  時系列に流れる出来事ではなく、ずっと持っておくものなので
- 後から**プロセスを切り出せる**。考えが行動に変わった記録が道として残る
- アストロラーベでは地金の節として、
  アイデアやログと同じ道の上に並ぶ
- 温度は持たない。冷めるのは「したいこと」であって、良いと思った考え方ではないため
- プロセスを抱えたままのインゴットは捨てられない（409）。道が切れてしまうので、
  先にプロセスを片付けるか断念する

実装上はアイデアと同じ器に `is_spell` の印を立てている。こうすると
プロセスの切り出しも、アストロラーベの道もそのまま効く。

## 書き留める

思いついた時点では、種別も詳細もまだ決まっていないことが多い。
右下の ＋ は**題だけを受け取り、入れても閉じずに次を待つ**。

- ＋ は**どの画面にも出る**。思いつくのはどの画面を見ている時でも同じなので、
  ストリームまで移動してから、では間に合わない。物理キーボードなら `n` でも開く
- 入れると入力欄が空になって次が打てる。下に「入れたもの」が積み上がり、
  題を押せばその場で詳細へ行ける
- **複数行を貼れば1行ずつ入る**。1行の入力欄は改行を持てないので、
  貼り付けを拾って割っている。空行は飛ばす
- 種別は前に選んだものを覚えている。続けて書くときは変わらないことがほとんどなので
- 保存を待たずに入力欄を空にする。待たせると次が打てない
- **変換中は受け取らない**。確定の Enter で送ってしまうと打ちかけの文字が入る
- 閉じたときに、下の画面へまとめて反映する

## 買ったもの（家計簿として）

出来事という出来事が無くても、ふだんの消費は記録する。
買ったものは**消え物か残るものか**の二択で分ける。

| 別 | 中身 | 盤の上 |
|---|---|---|
| **糧**（`food`） | 食べ物など、使えば消えるもの | 残らない |
| **装備**（`gear`） | 道具・器・衣類など、手元に残るもの | 節として残る |
| （なし） | 出来事としてのログ | 節として残る |

- ＋ から**題と金額だけ**で入る。糧か装備を選ぶと金額の欄が出る
- 実装はログの器に `goods` の印を立てるだけ。こうすると**試験管の消費済み・
  レガシー・金庫がそのまま効く**。買い物のためのテーブルは足していない
- ストリームは 糧／装備 で絞れる。カードの色は糧＝薬草色、装備＝鋼の色
- 後から付け替えられる。ログの詳細で 出来事／糧／装備 を切り替える
- **糧はアストロラーベの盤に出さない。**食べれば消えるものなので、
  買った回数だけ節が増えると盤が読めなくなる。装備は残るので節になる
- ホームに**今月の出どころ**を出す。糧・装備・出来事の3つを帯で並べる。
  数字だけだと割合が読めず、家計簿として見るときに効かない

まとめて貼ったときは、**金額は1行目にだけ載せる**。
同じ額を全部に配ると嘘になるため。

## アイデアの温度

> **いまは伏せてある。**`public/app.js` の `SHOW.temperature` を `true` に戻せば出る。

アイデアには温度（K表記）がある。**273K（0℃）を常温＝基準**とし、
熱を入れてから触らずにいると基準へ向かって冷めていく。

- スライダーで 273K〜373K を設定する。設定すると冷却の起点が今にリセットされる
- 冷却は半減期方式。半減期ぶんの日数が経つごとに、273K からの差が半分になる
  （既定30日。半減期30日・370Kなら 30日後に322K、60日後に297K、180日後に275K）
- 半減期は 設定 → アイデアの冷却 で変えられる。**0 にすると冷めない**
- 温度は保存された値そのものではなく、読むたびに経過時間から計算する。
  つまり冷却のためのバッチ処理は無く、半減期を変えれば過去のアイデアの温度も即座に変わる

熱さは 沸騰（350K〜）／熱い（320K〜）／ぬるい（295K〜）／冷めかけ（276K〜）／凍結（〜275K）で
色とアイコンが変わる。凍結だけ炎ではなく霜の結晶になる。

なお、プロセスを切り出すなどの操作で自動的に熱が戻ることはしていない。
温度を動かすのは明示的な操作だけなので、冷めていることに気づいたら自分で入れ直す。

## プロセスの期日

プロセスには **いつから（開始日）** と **いつまで（期限）** を任意で付けられる。
どちらも `YYYY-MM-DD` のローカル日付で、片方だけでもよい。

- プロセス画面は **期限順** と **新しい順** を切り替えられる。既定は期限順
- 期限順は「期限の近いものから並べ、期限の無いものは末尾」。
  末尾に何件あるかは一覧の上に出す
- 進行中のものだけ、残り日数をバッジで出す。
  超過（赤）／今日まで（金）／あと3日以内（金）／あとN日（淡色）／N日後に開始
- 日付はカードの「日付を決める」を開けばその場で変えられる。空にすれば外れる
- 期限が開始日より前だと 400 を返す

**大釜にも同じ日付を持たせられる。素材は自分の期限が無ければ大釜の期限を引き継ぐ**
ので、大きなイベントには大釜側に一度だけ日付を振れば足りる。
素材に自分の期限を入れればそちらが優先され、大釜の日付を変えれば引き継いでいる
素材だけが追随する。並び替えもこの実効の期限で行う。

ホームの進行中プロセスと、アイデア／ログ詳細のプロセス一覧も期限順で並ぶ。

## 金庫

**月が終わると、その月のウォレットの余りが金庫に積まれる。**
ホームの試験管の下と、設定から開ける。

- 積まれるのは `全体 − 消費済み`。**進行中の今週はまだ積まない**
- 使いすぎた月はその分だけ目減りする。マイナスもそのまま反映する
- **初期残高**を設定できる。使い始める前から持っていたぶんを入れておく
- 対象は最初のログがある月から先月まで。ログを取り始める前の月まで遡って
  「使わなかったぶん」を積むと嘘になるため
- 週ごとの内訳（全体・消費済み・差額）を並べるので、残高の根拠を追える

残高は保存せず、読むたびに週ごとの差額から計算する。使える量を後から直せば
金庫の残高もその場で追従する。

## 週のタイムを表で選ぶ

設定の「週のタイム」は、**曜日×24時間の表を指でなぞって塗る**。
塗ったマスの数がそのまま週のタイム（1マス＝1時間）になる。

- 最初に触ったマスの逆の状態を、指を離すまで塗り続ける。
  塗るときも消すときも同じ操作
- 塗っているあいだ画面がスクロールしないよう、表は `touch-action: none`。
  左の時刻の目盛りは通常どおり触れるので、そこを持てばスクロールできる
- 塗りは168文字の 0/1 として `settings.time_grid` に持つ。
  保存すると `weekly_time` が塗ったマス数から再計算される
- 表がまだ空で、数値で設定した値が残っている場合は、その値を注記に出す。
  塗って保存するまで置き換わらない

週ごとの個別設定（前掲）は数値のままで、表とは別に効く。

## 大釜（プロセスのTODOリスト）

> **いまは伏せてある。**`public/app.js` の `SHOW.cauldron` を `true` に戻せば出る。

ひとつの大きなイベントに必要なプロセスを、**素材**としてまとめて並べる器。
大釜はアイデア／ログにぶら下がり、素材はその大釜に入ったプロセスになる。

- 素材は1行1つのテキストでまとめて投入できる
- 素材が1つ以上あって、**断念を除く全部が完了**すると錬成が終わる。
  逆に完了を取り消したり素材を足したりすると、錬成中に戻る
- 断念した素材は「要らなくなったもの」として必要数から外れる
- 大釜を捨てても素材は消えない。単独のプロセスに戻るだけ

素材も普通のプロセスなので、完了すればログが生成され、リソースの集計も
今までどおり効く。大釜が増やすのは「まとめて並べて、そろったかを見る」という
見え方だけで、リソースの数え方は変えていない。

## 繰り返すプロセス

プロセスは**一回きり**と**繰り返す**に分かれる。プロセスの画面はこの2つで切り替える。

繰り返すほうは**周期（日）だけを持つ「種」**で、そこから一回きりのプロセスが生えてくる。
生えたものは自分で立てたものと同じに扱えて、完了も断念もできる。
種と、種から生えたものには**循環の印**（2本の弧が輪になって追いかけ合う印）が付く。

- 無限には作れないので、**今日から90日先まで**を保つ。読むたびに足りないぶんを
  継ぎ足すので、使っている限り先が尽きない。一度に生やすのは60個まで
- **進行中の数は、種を1つと数える。**そこから生えたものは数えない。
  先まで生やしてあるぶんを足すと、増えるのは数字だけで中身は同じになる
- 過去に遡っては生やさない。止まっていた間のぶんは作らず、今日から拾い直す
- **種は完了できない**（409 を返す）。回り続けるものなので、終わるのは止めたとき。
  止めると、まだ手を付けていない先のぶんは引き上げる
- 種は期限を持たない。期限を持つのは生えたほうだけ
- **種は固定費として、可処分から先に引かれる**（前掲）。種の札には、
  毎週いくら持っていくかを出す。周期と見積もりから暗算はできるが、
  頭の中でやらせる理由がない
- 生えたほうは棚にも一覧にも出るが、リソースの数には入らない。
  もう払ったものなので、やっても残量は動かない

`mission` に `repeat_days`（周期）、`repeat_of`（どの種から来たか）、
`repeat_through`（どこまで生やしたか）の3列を足している。

## アストロラーベ

たまっていく情報を、**1枚の盤**として描く画面。天体の位置を読む器具に見立てて、
物事どうしの関わりを角度と輪で出す。

**何と何が関わっているかは、派生したプロセスだけが決める。**
タグのような別の分類軸は持たない。持つと同じことを2通りで表すことになる。

| 盤の要素 | 中身 |
|---|---|
| 節 | アイデア（賢者の石）／インゴット（地金）／ログ（足跡）。輪で描き、中は紙のまま抜く |
| 軌道 | プロセス。親の輪を子の角度まで回ってから、外へ抜ける |
| 崩落 | 断念したプロセス。軌道が点線に落ち、下敷きも暗くなる |
| 行き止まり | 完了していない軌道の先。空の節（掘削中は金、崩落は鈍色） |
| 大釜の節 | 同じ器に入った素材の束。輪の一部を緑にして「3/4」の進み具合を出す |
| 輝き | レガシー。節に金の輪をもう1本回し、軌道に星を添える |
| 灯りの軌道 | いちばん奥の掘削中まで。金の破線。盤ぜんたいで1本だけ |

- 入口はアイデア全部と、プロセス由来ではないログ。**いちばん内側の輪に並べる**
- **中心には何も置かない。**入口どうしは無関係で、線で結ぶと在りもしない
  関わりを描くことになる
- いちばん内側の輪の大きさは葉の数から決める。固定にすると、入口が増えたときに
  内側で節が重なって団子になる
- 大釜は素材ごとに輪を取らない。素材の先にさらに道が続いているものだけ、
  大釜から枝として伸ばす
- 節を押すとその詳細へ飛ぶ。押せるのは絵ではなく節ぜんぶ

### 盤に載せる期間

既定は**直近1か月に動いた道だけ**。全部を載せ続けると、何年ぶんかの記録が
いずれ盤を埋めて読めなくなる。古いかどうかはその道でいちばん新しい出来事で
決めるので、入口が古くても最近も掘っているなら現役として残る。

期間を指定すると、当時の盤をそのまま呼び出せる（**エフェメリス**＝ある日付の
天体の位置をまとめた暦表）。`/api/dungeon?since=&until=` で受ける。

### 盤に見せるための決めごと

- **滲みはぼかしで作らない。**同じ中心の輪を段で重ねる。ぼかすとこの画面だけ
  輪郭が溶けて、他と手ざわりが変わってしまう
- 地は紙のまま。夜空に浮かべていた頃の星は、昼の紙に合わないので紙の斑に変えた
- **葉から順に持ち場を配り、親は子の平均に置く。**これで枝が扇に開く
- **軌道は必ず輪に沿わせる。**斜めに直線で結ぶと蜘蛛の巣になる
- 節が乗る輪は、薄い案内線として先に敷いておく
- **盤は縦長の楕円にする。**真円のまま置くと、縦長の画面では上下が余って、
  そのぶん盤が小さく縮む
- **節が居るところだけを切り出して映す。**輪はいちばん深い道の形で決まるので、
  全体を映すと誰も居ない外側の輪ぶんだけ盤が縮む
- 盤の画面は段にも割らず流しもせず、残りの高さを全部盤に渡す

**レガシー**は、ログと**完了した**プロセスにつけられる印で、盤の上で輝く。
進行中・断念のプロセスには付けられない（409 を返す）。輝かせるかどうかだけの
印なので、一覧も絞り込みも持たない。

## MVP の範囲

要件定義の 6.1〜6.5 を実装している。

- ストリーム（種別フィルタ、＋からの追加。＋は全画面に置き、連続で書ける）
- アイデア／ログ詳細（タイトル編集、プロセス追加、紐づくプロセス一覧）
- プロセス（ステータス別フィルタ、元エントリへのリンク、完了／断念）
- ホーム（タイム／ウォレットの試験管、全完了時の残量）
- 設定（週あたりのタイム、月あたりのウォレット）

要件に無いが操作の行き止まりを避けるために足したもの:

- ログ詳細での実消費（タイム／ウォレット）の入力 — 「ログ直接入力で確定」する経路
- 断念したプロセスを進行中に戻す操作
- 使える量の期間ごとの個別設定（前掲）。要件 6.5 は単一の値だけだが、
  週・月ごとに実態が変わるため既定値からの上書きを持てるようにした
- 繰り返すプロセス、アストロラーベ、レガシー、大釜（前掲）

フェーズ2のうち、アイデアの温度は実装済み（前掲）。
プロセスの「未着手」「保留」、週カレンダーによる時間の
範囲選択はまだ。

## 見た目

**地は紙、差し色は葉の緑。**面を明るく起こし、沈めるのは入力欄などのくぼみだけにする。
実り（金）は宝箱・消費予定・期限・金額にだけ残す。中世ファンタジー寄りの語彙はそのまま。

紙の上では金は文字に使えない（`#a8802a` で白地に 3.4:1）。
**塗りには `--gold`、文字には `--gold-dark`** と使い分けている。

- 絵情報はすべて**ドット絵**。`public/icons.js` に 16x16 のグリッドを文字で持ち、
  横に連続する同色をまとめて `<rect>` に変換する。外部画像は使わない
- アイコンは **アイデア＝賢者の石、ログ（出来事）＝歩いた足跡、プロセス＝丸底フラスコ**。
  ほかに設定＝鍵、レガシー＝宝箱、アストロラーベ＝石の門、
  インゴット＝原石、循環＝輪になった2本の弧、金庫＝積んだ金貨、
  アイデアの温度＝炎（冷めきると霜の結晶）、大釜＝鍋。
  炎は熱さに応じて配色だけ差し替える
- リソースは**2色の試験管**。下から順に、消費済み（薬草色）と消費予定（琥珀・斜線）。
  残量は空のガラスとして残り、全体を超えると管の縁が赤くなる
- **図案は紙の上で読める濃さに落としてある。**足跡・鍵・紋・炎・霜は単色で輪郭を
  持たないので、暗い地のままの明度だと白地で沈む。平均明度が 168 を超えたものを
  一段ずつ落とした（`iconBody()` の矩形から測れる）
- 書体は **Kaisei Opti**（Font-Kai／SIL OFL 1.1）を同梱して使う。見出しも本文も同じ。
  後ろに積んだシステムの和文書体は、書体が届くまでのあいだと、字が欠けたときの受け皿。
  和文を先頭に置くのは、欧文書体を先に書くと欧文だけ西洋の書体になり、
  和文はシステム任せになって翻訳物のような字面になるため
  （iOS/macOS はヒラギノ、Windows は游書体／BIZ UD、Android は Noto。
  末尾の IPA は Linux 向けの保険で、総称に落ちて中国語の書体が当たるのを防ぐ）
- 書体は**元の TTF をそのままは置かない**。1つ4MB超あるので、WOFF2 に詰め直したうえで
  符号位置で切り分け、`unicode-range` で必要な切れ端だけ落とす。
  ふだんの画面は欧文・記号・かなの約130KBで足りて、漢字は書いた字に当たったぶんだけ来る。
  太さは CSS に出てくる 400 と 700 だけ。`font-display: swap` なので、
  届くまではシステムの明朝で読める。詳しくは `public/fonts/README.md`
- 数値は要件どおり等幅。欧文の等幅を先に書き、仮名・漢字だけ和文書体に落とす

質感は次の4点で作っている。平坦な単色・均一な枠のままだと安く見えるため。
ただし**ぼかしは一切使わない**。にじんだ影となめらかな諧調はドット絵と喧嘩し、
輪郭が溶けて締まらない。

- **すべて平塗り**: 面は単色。立体は `inset 1px 1px 0` の明線と
  `inset -1px -1px 0` の暗線、2本だけで起こす。`box-shadow` にぼかし半径は
  1つも無い（`grep -oE 'box-shadow:[^;]*' | grep -E '[0-9]+px [0-9]+px [1-9]'`
  が空になる状態を保つ）
- **紙の粒**: 全面に SVG の `feTurbulence` をごく薄く敷く。外部画像は使わない。
  白地では乗せると飛ぶので `mix-blend-mode: multiply` で沈める
- **額装**: パネルは薄い縁で締め、内側に葉の細い罫を1本回し、四隅に鉤を置く
- **差し色は安売りしない**: 葉の塗りはフォームの確定動作と現在の選択にだけ使う。
  カードの上で繰り返し出る「完了」は**輪郭だけの葉**（`button.act`）にして、
  塗りつぶしと見分けが付くようにする

文字の読みやすさは実測で確かめている。前景と背景の対比を全画面で測り、
小さい字は 4.5:1、18px 以上は 3:1 を下回らないようにした。
これで葉は `#4a8236`（白抜きの文字で 4.6:1）、補助の文字は `#656b5e` に落ち着いた。
残っているのは送れない側の矢印だけで、これは効かないことを示すためわざと薄い。

押しやすさも同じように測っている。実機を触らずに確かめられる数字なので、
`a / button / input / select / summary` の寸法を全画面で拾い、
**短辺 32px を切るものを残さない**ようにした。

- 高さの下限をまとめて置く。`button` は 40px、入力欄と `summary` は 44px。
  ページ送りの矢印だけは主要な移動手段なので 52×44 と決め打ち
- **見た目を変えたくないところは、判定だけ広げる。**上部のアイコン（36px 角）と
  大釜のチェック（28px 角）は、透明な `::after` を 44px 角で重ねてある。
  上部のアイコンは隙間を 8px 取ってあるので、44px の判定がちょうど接して
  重ならない。隣に取られないことは `elementFromPoint` で確かめている
- 時間の表だけは例外。指で塗る面なので、1マスを的として扱っていない

グラデーションを残しているのは、段で塗ることに意味がある場所だけ。
試験管の液（3段）、温度スライダーの目盛り（5段）、見出しの罫（1pxの線2本）。
いずれもハードストップで、なめらかに混ぜていない。

タブは要件の3つに **アストロラーベ**を加えて4つにした。
つながりを見る画面は他から辿らせるには主役すぎるため。

## 伏せてある機能

多いと感じたものは、消さずに伏せる。表も API も保存済みの値もそのままなので、
旗を戻せば続きから使える。旗は `public/app.js` の頭に1か所だけ置いてある。

```js
const SHOW = { temperature: false, cauldron: false };
```

伏せるときの決めごと：

- **伏せたせいで触れなくなるものを作らない。**大釜に入っているプロセスは、
  伏せている間は器から出して、ふつうのプロセスとして詳細にもアストロラーベにも出す
- **盤では節ごと落とさない。**大釜の節を消すと、その先に続く道まで盤から消える。
  素材を親の軌道として継ぎ直してから節だけ抜く
- 器から継いだ期日は残る。ただし「大釜 → 8/27」ではなく「→ 8/27」と出す。
  出どころの名前を出しても、その画面には出どころが無い

## 画面に説明文を置かない

機能は一度使えば分かるので、操作の手引きは画面に書かない。
書いてあるのは、**使っても気づけないこと**だけ。

- 隠れた特例 — 冷却の「0 で冷めません」。0 を入れない限り出会わない
- 食い違っている時の断り — 週のタイムを数値で入れてある状態で表を開いたとき

これ以外は落とした。空の画面の文言も名詞止めにして、句点まで削っている。
地図の凡例は畳んでおく（記号は地図の中にも文字で出るので、ふだんは要らない）。

## ページ送り（スクロールしない）

画面は**流すものではなく、めくるもの**として扱う。
`html, body` で縦スクロールを止め、シェルは `100dvh` の柱に固定する。
上端の見出し・下端のタブ・ページ送りは動かず、真ん中の1画面だけが差し替わる。

- 中身は `#view` の**段組み**（`column-fill: auto`）に流し込む。1段＝1画面なので、
  各画面の描画側には手を入れずにページが割れる
- **2画面ぶんぐらいまでは、めくらずに縦へ流す**（`.view.is-scroll`）。1画面に少し
  足りないだけで送る操作を強いるほうが、指の手数が増える。これを超えると
  いつまで続くのか分からない縦長になるので、そこからめくりへ切り替える
- **どちらにするかは、段に割る前の丈で決める。**段を外した状態の
  `scrollHeight ÷ clientHeight` を四捨五入して2以下なら流す。
  2.4画面は流し、2.6画面はめくる
  - 段の本数で決めていたが、枠を割らない指定のせいで段の末尾に白が残るため、
    2画面ぶんの中身が3段にも4段にもなる。それを頁数と読んでいたので、
    流せるはずのものがめくりに回っていた
  - 丈で測ると「1段しかないから1ページ」という取り違えも起きない。
    段を外した状態は流したときの見た目そのものなので、判定と結果が食い違わない
- めくるほうに回ってから、段に割って何段になったかを数える。それが頁数になる
- 送りは `scrollLeft` でやる。`overflow: hidden` でも JS からの代入は効くので、
  指では動かないまま送れる
- 何ページに割れたかは `MutationObserver` で `#view` の変化を見て測り直す。
  描画関数それぞれに「測り直せ」と書いて回らずに済む。
  図版や書体が遅れて寸法を決めることがあるので、落ち着いた頃にもう一度だけ測る
- 送る手立ては3つ。**指で横に払う／下の ◀ ▶ ／ 矢印キー**。
  縦の動きが勝っている払いは、ただの押し損ねとみなして無視する
- **矢印だけは 44px を切らせない。**払えると分かる前に狙うのはここなので、
  ここで外し続けると「送れない画面」に見える
- 地図・時間の表・文字入力の中では払いを拾わない。そちらの操作が主だから

ページの割れ方は2段構えにしてある。

- 枠のあるものは境で割らない（`break-inside: avoid`）。断ち切られると別物に見える
- ただし**大釜のように1画面近い高さになりうる容器は割れるようにする**。
  割らないと、入りきらないぶんが丸ごと次ページへ送られて前のページが白く空く。
  枠は `box-decoration-break: clone` で割れた先にも引き直す
- 見出しだけが前のページに取り残されないよう `break-after: avoid` を置く

**地図だけは枠の中で動かす。**ページを割ると道が断ち切れて読めなくなるので、
1枚の紙に載せたまま、覗き窓（高さ `min(340px, 38dvh)`）を動かして見る。
これは画面のスクロールではなく、地図を繰る操作として扱っている。
