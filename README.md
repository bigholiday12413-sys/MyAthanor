# MyAthanor

個人用リソース・アイデア管理ツール（MVP）。

**日々のやることを錬金術に見立てる。**タイムとウォレットという2つのリソースを
注ぎ込んで成果物を作る、という筋で言葉と絵を揃えてある。
日々のやることは**フラスコ**（プロセス）、意思や思いつきは**宝石**
（アイデア）として持つ。

日々の思いつきを**アイデア**として書き留め、そこから**プロセス**を切り出して、
消費する **タイム／ウォレット** を見積もる。
**プロセスは「予定」、ログは「行ったこと」で、同じものの前後の姿。**
プロセスを完了すると、そのままログに移る。
ホームの試験管で「消費済み・消費予定・残量」を常時把握できる。

## プロセスとログ

**予定していることをプロセス、行ったことをログと呼ぶ。**予定を経たかどうかに
かかわらず、済んだものはログ。この2つは別のものではなく、同じ1件の前後の姿。

```
アイデア ──切り出す──▶ プロセス（予定）──完了──▶ ログ（行ったこと）
                                    買い物などは最初からログ ─┘
```

- **完了するとプロセスの行は畳まれ、ログに移る。**両方を残さない。
  2つの器に同じものが居ると、片方だけ直す・片方だけ消すが起きる
- 見積もりはそのまま実績として写す。**出どころ（どのアイデアから来たか）と
  輝きも連れて行く**ので、盤の道は切れない
- 買い物（糧・装備・祭事）は予定を経ないので、最初からログとして入る
- **予定（プロセス）は、それを出したアイデア・ログの側にだけ居る。**
  一覧としては流さない。丸底フラスコで、満ちているほど先の話、
  期限が近いほど中身が減る
- **タブは行ったこと（ログ）だけを流す。**絞り込みは 糧／装備／祭事／プロセス
  ／**循環**。前の4つは別（何であるか）で、循環だけは出どころで絞る。
  プロセスは別を付けていないぶん──プロセスの完了で生まれたログと、
  素のまま書き留めたログ。フラスコは注ぎ終えて空になった姿で出す。
  満ちたフラスコ（予定）と空のフラスコ（済んだ）で、前後の姿を絵でも分ける
- **アイデアのタブはアイデアだけ**を流す。源はアイデアで、そこから先は
  すべてプロセス／ログの側の話になる
- **アイデア産のプロセスは、件数の札ではなく実の題を字下げで出す。**
  「プロセス3件」だけでは何をやる気だったか思い出せない。1件ずつは軽く
  一行で（見積や期限までは出さない。詳しくはアイデアを開けば札で見える）。
  進行中のものだけを出し、済んだものは無くなる
- **循環は生えたぶんだけを出す**（いちばん近い1回）。種も並べると、一行しか
  出さない札の上では同じ題が2つ並んで見分けが付かない。種そのものは詳細の
  一覧に居るので、周期を直す道は塞がらない

## アイデアの終わり

アイデアは切り出したプロセスが尽きても、それ自体は終わらない。
**アイデアそのものを終える**ボタンをアイデア詳細に置き、押すとアイデア自身を
出どころとするプロセスが1件立つ（題はアイデアと同じ）。あとは他のプロセスと
同じに扱え、完了すればログへ移る。

- **アイデアがそのままプロセスになったもの**として扱う。子のプロセスとは
  出自が違うので、**予定の段階から絵はフラスコではなく金の宝石**にする。
  題もアイデアと同じままで、札には「終わり」の語を添える
- **完了しても金色の宝石のまま**ログへ移る。子のプロセスの完了（空の丸底
  フラスコ）とは重さが違うので、絵で見分けられる
- **終わりは1つでよい。**すでに予定に立ててあるあいだはボタンを出さない。
  押すたびに増える理由がないため
- 完了した後にもう一度押すことはできる。終える瞬間をやり直したくなること
  自体は止めない
- `mission` と `log` に `is_conclusion` 列を持たせているだけで、
  アイデア側には何も足していない。アイデアの状態（済んだかどうか）は、
  この列を持つログが出どころに繋がっているかどうかで読む

## 起動

```bash
npm install
npm start          # http://0.0.0.0:3000
```

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `PORT` | `3000` | 待ち受けポート |
| `HOST` | `0.0.0.0` | 待ち受けアドレス |
| `DB_PATH` | `data/myathanor.db` | SQLite ファイルの場所 |

`npm run dev` はファイル変更で自動再起動する。

DB は初回起動時に自動作成される。バックアップは `data/` をコピーすれば足りる。

### スマホから使う

`0.0.0.0` で待ち受けているので、ホストPCの Tailscale アドレスに
`http://<tailscale-name>:3000` でアクセスする。認証は持たない
（要件どおり Tailscale のネットワーク層制限のみを前提とする）ので、
**Tailnet の外に公開しないこと**。

### 見本版（GitHub Pages）

サーバを立てずに、URL を開くだけで触れる見本を `main` への push ごとに出す。
スマホから見た目と操作感を確かめるためのもの。

```
https://bigholiday12413-sys.github.io/MyAthanor/
```

**初回だけリポジトリ側の設定が要る。**
Settings → Pages → Source を **GitHub Actions** にしてから、
Actions → Pages → Run workflow で一度流す。

これを workflow 側から自動でやることはできない。サイトの作成はリポジトリの
**管理権限**が要り、workflow の `GITHUB_TOKEN` には無いため
（`permissions: pages: write` は配信までしか届かない）。
`configure-pages` に `enablement: true` を渡すと
`Resource not accessible by integration` で落ちる。
`main` に入る前に見たいときは、Actions → Pages → Run workflow でブランチを選べば出る。

**出るのは見本版だけで、持ち主のデータは1件も載らない。**
見本版は `demo/seed.js` の作り物をブラウザの中の SQLite に入れて動いていて、
`data/myathanor.db` は組み立てにも配信にも関わらない。

仕組みは「本体のコードをそのまま持っていき、DB の1ファイルだけ差し替える」。

- `src/store.js` は `node:sqlite` を直接は触らず、`./db.js` の `db` を使っているだけ。
  そこへ WASM の SQLite（sql.js）を同じ形でかぶせた `db.js` を置くと、
  **store.js も routes.js も1行も変えずにブラウザで動く**
- `/api` への fetch を横取りして `src/routes.js` に渡す。express の `Router` は
  使っている範囲だけ真似たものに差し替える（`demo/express.js`）
- つまり**見本版と本体でロジックが別物にならない**。画面・集計・状態遷移は同じものが走る
- データは端末の localStorage に残り、初回だけ見本を入れる。「最初に戻す」で消せる
- スキーマは `src/schema.js` に切り出して両方から使う。片方だけ列が増えることがない
- **`index.html` も本体のものから組み立てる。**写しを持つと、タブの名前を変えたときに
  片方だけ古いまま残る（実際に「ミッション／ダンジョン」のまま出ていた）。
  違うのは見本である断りと、読み込む部品の3点だけなので、`demo/banner.html` を
  差し込み、更新の知らせとサービスワーカーを外して作る。
  組み立ての最後に、消したはずのものが残っていないか・入るはずのものが入ったかを
  文字列で当たっている

```bash
npm run build:demo   # site/ に組み立てる
```

見本の日付は「今」から逆算して入れている。置いた日付を焼き込むと、
時間が経つほど古びて、期限や試験管の見え方が変わってしまうため。

### 常時起動させる

ノートPC で常駐させる場合の systemd user unit の例:

```ini
# ~/.config/systemd/user/myathanor.service
[Service]
WorkingDirectory=/path/to/MyAthanor
ExecStart=/usr/bin/node --no-warnings=ExperimentalWarning server.js
Restart=always

[Install]
WantedBy=default.target
```

```bash
systemctl --user enable --now myathanor
loginctl enable-linger "$USER"   # ログアウト後も動かす
```

## 構成

```
server.js          Express アプリ（API + 静的配信 + SPA フォールバック）
src/db.js          SQLite 接続
src/schema.js      スキーマ（本体と見本版で共用）
src/period.js      週（月曜始まり）／月の集計期間と日付ユーティリティ
src/store.js       データアクセスと状態遷移
src/routes.js      REST API
public/app.js      Web UI（ビルド不要の ES モジュール）
public/icons.js    ドット絵アイコン（16x16 のグリッドから SVG を生成）
public/styles.css  見た目
demo/              見本版（GitHub Pages）だけで使う差し替え部品
scripts/           見本版の組み立て
```

依存は Express のみ。SQLite は Node 22 標準の `node:sqlite` を使うため
ネイティブビルドは発生しない（Node 22.5 以上が必要）。

## 単位の扱い

- **タイム**: DB には**分**の整数で保持し、UI は**時間**で表示・入力する
- **ウォレット**: **円**の整数

## リソースの集計

**タイムもウォレットも1週間（月曜始まり）**を1期間として、その期間の中だけを見る。
ウォレットも週に揃えたのは、2つの刻みを頭の中で行き来しなくて済ませるため。

**`入ってくる量 − 固定費` は、どの画面でも「使える量」と呼ぶ。**
以前は試験管で「全体」、設定で「週のタイム」「週のウォレット」と
3通りに呼んでいた。とくに「全体」は固定費を引いた後の数なのに、
語感は引く前を指していて紛らわしかった。

| | 集計対象 | 期間の絞り方 |
|---|---|---|
| 使える量 | 入ってくる量 − 固定費 | その期間ぶん |
| 入ってくる量 | 報酬の週割り（または個別設定）＋ **入ってきたぶん** | その期間に済んだ収入と、循環の収入の週割り |
| 消費済み | ログの `time_spent` / `money_spent` | その期間に起きたログ |
| 消費予定（プロセス） | 進行中プロセスの見積もり | **期限がその期間の終わりまでに来るもの**。期限切れも含む |
| 残量 | 使える量 − 消費済み − 消費予定 | ＝「その期間ぶんをやり切ったときの残り」 |

**循環から来るものは、消費済みにも消費予定にも乗らない。**固定費として先に
引いてあるので、そこで数えるとひとつの出費を二度引くことになる。
どの種から来たかは `log.repeat_of` が持つ（完了で移るときに連れて行く）。

**入ってきたぶんは消費済みに乗らず、入ってくる量に足される**（後掲）。
額を `money_gained` という別の列で持つので、消費済みを数えている問い合わせは
どれも直さなくてよい。

期限を持たないプロセスは試験管に乗らない。**代わりにホームへ別枠で出す**ので、
乗っていないことに気づける（見積もりが 0 のときは出さない）。
種は期限を持たないが、固定費として乗っているのでこの別枠には出さない。
期限切れのプロセスを今期に含めるのは、過ぎていても払う／やるぶんだからで、
視界から消すと危ないため。

期間の境界はサーバのローカルタイムゾーンで判定する。

### 固定費 — 繰り返すものは月の収入と同じ扱いにする

**繰り返すプロセスは「決まって出ていくもの」なので、月の収入と同じ側で相殺する。**
毎回どうするか決めるものではないから、週ごとの消費予定として立てない。

```
その週に使える量 ＝ 入ってくる量 − 固定費の週割り
                      ↑報酬÷4 または週のタイム
```

- 種の見積もりは1回ぶんなので、**1週あたりは `見積 × 7 ÷ 周期`**。
  周期30日のものは月ぶんがちょうど戻る
- **タイムもウォレットも同じ扱い。**毎週2時間の掃除は、時間の固定費に他ならない
- **個別設定の週からも引く。**可処分の定義をひとつに保つため。設定画面の入力欄が
  受け取るのは「入ってくる量」で、固定費を引いた後の数はその下に出す
- **固定費に赤も符号も付けない。**赤字ではなく、毎週きまって出ていくぶんで、
  性質は消費済みと同じ。赤はこのアプリでは使いすぎの合図なので、当たり前に
  出ていくものに使うと、いつも何か起きているように見える
- 固定費が入ってくる量を超えると使える量が負になる。そこは赤で出して、
  そのままにする。丸めて隠すと赤字に気づけない

週ごとに立てると、家賃の来た週だけ真っ赤になって、他の週が実態より豊かに見える。
均せば、どの週も「固定費を払ったあとに手元に残るぶん」を出す。
これは要件に無いが、月の収入と月の固定費を別々に扱うと、
週で暮らすという前提そのものが成り立たないため入れた。

### 貯金のように「使わずに取っておく」を扱う

欲しいものをアイデアとして立て、その貯金を**期限つきのプロセス**にすると、
給料日までのあいだ試験管に琥珀色で立ち続ける。残量＝実際に使ってよい額になるので、
残量を見て暮らすだけで貯金分が守られる。貯金したらプロセスを完了すれば、
消費済みへ移って確定する。

毎月続くものは**繰り返すプロセス**にする。周期を入れておけば固定費として
先に引かれるので、残量を見て暮らすだけで済む（前掲）。

## ホームの並び

上から**週の紙 → リソース → 調合棚 → この1週間**。数を並べる枠（現況）は置かない。

**週の紙**は7枚を月曜から並べたもので、終わった曜日から順に印が入る。
今日の紙にはまだ印を入れない。終わっていないから。
曜日の文字は出さない。左から月曜と決まっていて、印の数で何日目かが読める。
読み上げには要るので、曜日名は `aria-label` にだけ残す。
数字を読む前に「いま週のどこに居るか」が目に入るようにするためのもので、
タイムもウォレットも週で見るようになったので置いた。

進行中のプロセスの一覧はホームに置かない。予定はそれを出したアイデア・ログの
側にだけあり、同じ札をもう一か所に出したりはしない。

**調合棚**は、**今日から7日先まで**に期限が来るプロセスを丸底フラスコとして並べたもの。
暦の週ではなく今日を起点にするのは、週の後半になるほど棚が短くなるのを避けるため。
期限の早い順で、中身の高さが残り日数。期限が近いほど減っていて、
過ぎたものは空になり、放っておかれた分だけヒビが増えて、最後に砕けて消える
（棚番が気づいて次の巡りには新しい姿で戻ってくる、という体で無限に繰り返す）。
上の試験管と同じガラスの一家にしてあるので、同じ工房の棚に見える。
日数は書かない（液の高さとヒビの入り方で読める）。

- **満タンにはしない（最大8割）。**口まで詰まっていると、揺らせば溢れるように
  見えて落ち着かない。実際の調合も口いっぱいには入れない
- 液は2色。地を暗くして、水面と左肩に明るいほうを1段だけ置く。
  全部明るいと平たく見える
- **期限切れは吹きこぼれではなく、ヒビが入って砕ける。**放置した時間の長さを、
  溢れる量ではなく壊れていく体で見せる。ヒビは段を追って増え、砕ける瞬間だけ
  肩・左半身・右半身の3つに割れて飛び散り、また無傷の姿に戻って繰り返す。
  フラスコごとに開始位置をずらしてあるので、並んでいても同時には割れない
- **数は棚のフラスコの数がそのまま。**別に数字を書かない
- **先のプロセスは並べない。**期限を短く切るのは持ち主の運用で、
  遠い先まで並べると、いま見るべきものが埋もれる
- **繰り返しから生えたフラスコには循環の印**を重ねる。棚を見ただけで
  「これは勝手に来たぶん」と分かる。別枠に吊るしたりはしない
- **棚番**（白い布をかぶり、黒い魔女帽を斜めにかぶった2等身のもの）が、
  フラスコと同じ段を歩く。大きさもフラスコに揃えてあるので背丈が並ぶ。
  1歩に3秒。端まで行くと**10秒ほど姿を消し**、向きを変えて戻ってくる。
  止まる場所はフラスコの位置とちょうど重なる
  - 歩く柄を3枚持ち、1歩ごとに次の柄へ移る。輪郭は変えず、布の影と裾の位置を
    1ドットずらすだけ。輪郭まで動かすと、この大きさでは別人に見える
  - **フラスコが1本のときは歩く先が無いので、その場で柄の数だけ拍を打つ。**
    位置は変えられないが、柄が巡り、同じように消えて戻ってくる（一周38秒）。
    ずっと立ちっぱなしだと、居るのではなく描き損ねたように見える
  - 道筋は本数で変わるのでその場で組み、**`@keyframes` ではなく
    `element.animate()` に渡す**。刷ったCSSを差し込む形だと、規則が入るのと
    要素に名前が付くのとの前後で動き出さないブラウザがあり、確かめようがない
    不確かさが残る。JS から直に渡せばその前後関係が消える
  - 各点に `step-end` を付けて中割りを止める。中割りするとドットが半端な位置に来る
  - 動かすのは `transform` と `opacity` だけなので合成で済み、フラスコが
    何本あっても値段は変わらない（10秒あたりの仕事量は、動かさない場合と
    同じ 1ms 前後）
  - `prefers-reduced-motion` は **JS 側で見て、動きを付けない**ようにする。
    CSS の `@media` に書いていたが、要素に直接書いた `animation-name` に負けて
    効いていなかった
  - いつも横向き。布は前だけ開けて、前髪と鼻と顎の輪郭だけを出す。目は描かない
  - 裾に向けて丸めない。丸めると雪だるまになるので、真っ直ぐ落として裾で切り、
    後ろへ布を引きずらせる
  - 帽子はつばから立ち上げて途中で折り、先端を後頭部の側へ垂らす。
    真っ直ぐ尖らせると硬い三角にしか見えない
  - 帽子のぶん縦に伸びるので、この絵だけ 16x20 で持つ（他は 16x16）

**金庫**は枠を持たず、ウォレットの試験管の足もとに置く。
タイム側は貯まるものが無いので空けてあるが、枠は残す。
片方だけ丈が変わると、2本の管の目盛りがずれて見えるため。
差し引きには名前を書かない。上に引いた線と、緑と赤の使い分けで読める。

**ユーズド**（その週、何に出ていったか）はホームに置かず、**それぞれの試験管の
見出しから飛ぶ**。ホームは「いま週のどこに居るか」だけでよく、内訳は見に行くもの。
飛んだ先でタイムとウォレットを行き来できる。

- **ウォレットは別ごとにまとめる。**買い物は数が多くて似通うので、1件ずつ並べても
  割合が読めない。行からはストリームのその絞り込みへ飛ぶ
- **タイムは1件ずつ並べる。**時間を使ったことは数が少なく、どれも中身が違うので、
  まとめてしまうと「何に使ったか」が消える。多い順に並べ、行からはそのログへ飛ぶ

**この1週間**は、ホームのいちばん下に置く**過去7日ぶんの記録**（アイデア・ログを
新しい順に流したもの）。調合棚が「これから7日」を見せるのに対して、こちらは
「もう起きた7日」を見せる対になる帯で、下段が寂しくならないようにしている。
`GET /api/stream` に `since`（この日時以降）を足しただけで、アイデアのタブと
中身は同じ札（`streamCard`）を使い回す。

## 使えるリソースの管理

使える量は **タイムもウォレットも週単位（月曜始まり）** で管理する。
設定画面は2段構えになっている。

- **既定値**: 個別設定を持たない期間すべてに適用される
- **期間ごとの個別設定**: 特定の週だけ値を変える。`既定へ` で個別設定を消すと
  その期間は既定値に戻る

**ウォレットの既定値だけは、月あたりの「報酬」として持つ。**
入ってくる額は月で決まっているのに、使うのは週で見たいため。
設定に入れた報酬を **4で割った額**が、その週の既定値になる（`weeklyShare`）。
月を4週として割り切る。実際の週数（4.3週）で割らないのは、
端数の出ない数のほうが、暮らしの中で見当が付けやすいから。

個別設定は `budget` テーブルに `(kind, period_key, amount)` として持つ。
`period_key` はどちらも週の月曜日 `YYYY-MM-DD`。
既定値を後から変えても、個別設定を入れた期間の値は動かない。
月単位だった頃の `YYYY-MM` の行は読めなくなるが、消してはいない。
週のキーとして解釈できないものは黙って飛ばす。

設定画面の一覧には直近の期間に加えて、範囲外でも個別設定を持つ期間が必ず出る。
`さらに過去` でさらに遡れる。各期間には実際の消費済み量が並ぶので、
見積もりの妥当性をその場で確認できる。

### 設定は項目ベース。常に開いた入力欄を並べない

**設定画面のどの値も、ふだんは「値だけ見せる行」で、開けばその場で直る。**
`<details>` を項目として使い、閉じているあいだは編集の入り口が見えないようにする。

- **報酬・アイデアの冷却**（既定値）も、期間ごとの個別設定と同じ項目の形にする。
  常設の `<form>` を並べていたが、値を確認するだけの人にまで入力欄を見せる理由がない
- **期間ごとの個別設定がいちばん効く。**全期間ぶんの入力欄を常に並べていたが、
  実際に上書きするのはごく一部の週だけ。使わない欄まで常設すると、
  「個別設定という特例」が既定であるかのように見えてしまう
- 上書きしてある項目には `特例` の札を付ける。値だけ見ても、
  それが既定値なのか特別に入れた値なのかが分かるように
- 1件ずつ、開いた項目の中でその場で確定する。まとめて1回で保存する形は
  やめた。まとめて出す形だと、直したい1件のために全部の欄を目で追う必要がある

週のタイム（塗り表）はもともと項目（枡）を触る形だったので、そのまま。

## 書き留める

思いついた時点では、種別も詳細もまだ決まっていないことが多い。
**＋ は題だけを受け取り、押せば1件入って閉じる。**

**一段目は アイデア／プロセス／アイテム／祭事 の4つ**を2列に並べる。
糧と装備は「アイテム」にくくり、選んだときだけ二段目でどちらかを出す。
一段目に別を全部並べると、思いつきを1件入れるだけで選択肢を読む手間のほうが大きい。

```
[ アイデア ] [ プロセス ]
[ アイテム ] [ 祭事    ]
      └─ 選ぶと [ 糧 ] [ 装備 ]
```

- **金額の欄が出ないのはアイデアだけ。**思いつきにはまだ値段が付いていない。
  プロセス・アイテム・祭事は、その場で額まで入れてしまえる
- ＋ は**ホームにだけ出す**。どの画面にも浮かせていたが、読んでいる札や盤の隅を
  隠すだけで、思いついたら一度ホームへ戻ればよい。物理キーボードなら `n` でも開く
- **1回押したら1件。**控えに積んでいく作りだったが、何件も溜めると
  「入れたつもりで入っていない」が起きるし、溜めたぶんを見返すなら
  閉じてストリームを見たほうが早い
- 種別は前に選んだものを覚えている。続けて書くときは変わらないことがほとんどなので
- **変換中は受け取らない**。確定の Enter で送ってしまうと打ちかけの文字が入る
- 入ったら下の画面へ反映する

## 直す・消す

**書いたものは全部、後から直せる。**日時も含めて。
書き留めた時刻がそのまま正しいとは限らないし、思い出して足すこともある。

| もの | 直せるところ | どこから |
|---|---|---|
| アイデア | 題・**本文**・作成日時 | 詳細 |
| ログ（糧・装備・祭事） | 題・発生日時・別・消費タイム／ウォレット | 詳細 |
| プロセス | 題・見積（タイム／ウォレット）・**ウォレットの向き**・いつから／いつまで・周期 | 札の中の「直す」 |


プロセスは詳細の画面を持たない。**札の中で畳んである「直す」を開く**と、その場で
直せる。進行中でも完了でも開ける。後から書き換えられないものを作らない。
種は日付を持たないので、代わりに周期が出る。

**詳細は、開いた一覧のタブに居るまま出す。**戻る矢印もそこへ返す。
アイデアのタブに固定していたが、**＋ はホームにしか無い**ので、書き留めたものを
直そうとするたびに別のタブへ移されていた。書き留めてから直すまでが、
＋ を置いてある場所の中で閉じるようにする。

- ログのタブからは**絞り込みごと**覚える。装備を見ていたなら装備の並びへ戻る
- ユーズドから開いたものは、ホームではなくユーズドへ戻る
- 消した後も同じ一覧へ帰す
- 詳細のURLを直接開いたときだけホームへ返す（帰り先が無いため）

### 消したときに何が道連れになるか

**やらないことにしたものは消す。**「断念」という状態は持たない。やり直すなら、
そのとき新しく立てればよい。状態として抱えておくと、やらない札がいつまでも
一覧に居座って、いま見るべきものを押しのける。

- **アイデアやログを消すと、そこから出たプロセスも消える。**
  出どころの無いプロセスは、どこから来たのか辿れないまま残るだけになる
- **種を消すと、そこから生えたぶんも消える。**種だけ消しても回りは残らない
- **完了して生まれたログは残る。**出どころだけ外す。ログは「起きたこと」の記録で、
  段取りを消したからといって消えるものではない
- ログを消すと消費済みからも消えるので、リソースの集計はその場で戻る

消す前に、何件が道連れになるかを断りに出す。押した後で気づいても戻せないため。

## 買ったもの（家計簿として）

出来事という出来事が無くても、ふだんの消費は記録する。
**買ったものは、後に何が残るかで3つに分ける。**

| 別 | 中身 | 後に残るもの |
|---|---|---|
| **糧**（`food`） | 食べ物など、口に入れて消えるもの | 何も |
| **装備**（`gear`） | 道具・器・衣類など、手元に残るもの | 物 |
| **祭事**（`feast`） | 催しへの参加、旅、外での食事 | 見たこと・聞いたこと |
| （なし） | 物の出入りを伴わない、ただの出来事 | — |

**糧と装備は「アイテム」としてひとくくりにする。**どちらも物を買ったぶんで、
違うのは後に物が残るかどうかだけ。書き留めるときは まずアイテムを選び、
中で糧か装備かを決める（後掲）。

祭事を分けたのは、**物は残らないが消えたわけでもない**ぶんが、糧にも装備にも
収まらなかったため。同じ1万円でも、食べて消えたのか、道具になったのか、
その日限りの場に使ったのかで、振り返るときの意味がまるで違う。

- ＋ から**題と金額だけ**で入る。**登録のときに別を選ぶ。**
  金額の欄が出ないのはアイデアのときだけ
- **糧はアストロラーベの盤に出さない。**食べれば消えるものなので、買った回数だけ
  節が増えると盤が読めなくなる。装備は物が残り、祭事は見聞が残るので、どちらも節にする
- 実装はログの器に `goods` の印を立てるだけ。こうすると**試験管の消費済み・
  レガシー・金庫がそのまま効く**。買い物のためのテーブルは足していない
- **アイデアのタブはアイデアだけ**を絞り込み無しで流す。**ログのタブは
  糧／装備／祭事／プロセス／循環で絞り込む。**プロセスは別を付けていないぶん──
  プロセスの完了で生まれたログと、素のまま書き留めたログ
- 後から付け替えられる。ログの詳細で プロセス／糧／装備／祭事 を切り替える
- ユーズドのウォレット側は、この3つに**その他**（別を付けていないぶん）を足した
  4本の帯で出す。その他の行から飛ぶ先は、ログのタブの「プロセス」絞り込み

## 収入 — 別ではなく、プロセスの結果

**収入は「買ったものの別」ではない。**糧・装備・祭事は何を買ったかの分類だが、
入ってくる額はそこに並ばない。**入ってくるのはプロセスをやり遂げた結果**なので、
額の向きはプロセスが持つ。

**プロセスの見積ウォレットに「入ってくる」の向きを付けられる。**
完了すると、その額は消費済みではなく入ってきた側としてログに残る。
原稿を書く・不要品を売る・報酬を受け取る――どれも「やったから入ってきた」ぶん。

```
アイデア ──切り出す──▶ プロセス（入ってくる向き）──完了──▶ ログ（＋の額）
```

- **完了したログに別は付かない。**プロセスの顔（空の丸底フラスコ）のまま、
  額だけが＋で出る。収入という別を作ると、糧や装備と同じ並びに置くことになり、
  「何を買ったか」の分類に「入ってきた」が混ざる
- 額は `money_gained`、出ていくぶんは `money_spent` と**列を分ける**。同じ列に
  符号違いで入れると、消費済みを数えている場所すべてが収入を出費として拾う。
  分けておけば、今までの合計は1つも直さなくても正しいままになる。
  どちらの列にも額が入った行は作らない
- **ログを直しても向きは動かない。**向きはプロセスの側で決まっているので、
  題や日時を直しただけで出ていく側へ移ってしまわないようにする

### 使える量への効き方

**入ってきたぶんは、来た週の「入ってくる量」に足す**（消費済みから引くのではない）。
引くと「その週いくら使ったか」が実際より少なく見えて、家計簿として読めなくなる。

```
その週に使える量 ＝ 報酬÷4 ＋ その週の収入 − 固定費の週割り
```

- **効くのは済んでから。**入ってくる見込みは試験管に乗せない。まだ入っていない
  ぶんを足すと、来なかったときにそのまま使いすぎになる
- **消費予定にも乗せない。**出ていく話の中に混ぜると、稼ぐ予定を立てるほど
  使う予定が増えて見える。**タイムのほうは向きを見ない。**入ってくる仕事でも、
  やる時間は要るため
- **循環の収入は固定費の逆側に積む。**毎月の副収入のような種は、固定費から
  引くのではなく入ってくる量へ足す。固定費を負の数にすると、画面の
  「固定費」が符号だらけになる
- 金庫にもそのまま乗る。使える量が増えたぶん、使わなければ余りとして積まれる
- **週ごとの個別設定の入力欄に出すのは、収入を足す前の値。**足した後を出すと、
  開いて保存しただけで収入が個別設定に焼き付き、次からは二度足しになる

## ロスト — 失えるのは装備だけ

**装備は「後に物が残る」ぶんなので、その物が手元から無くなることがある。**
壊れた・失くした・人に譲った。ログの詳細に `失った` を置き、押すと印が付く。

- **糧と祭事は失えない**（409 を返す）。糧は食べれば消えるのが決まりで、
  祭事に残るのは見聞だから、どちらも「失う」の置きどころが無い
- **払った額は動かさない。**失っても払い戻されはしないので、消費済みも金庫も
  そのまま。持ち物から外れたという記録だけの印
- 記録としては消さない。買った事実まで消えると、何にいくら使ったかが記録から抜ける
- **絵は中身の抜けた兜**にする。満ちたフラスコと空のフラスコで予定と済みを
  分けているのと同じ読み方で、ここでは持っているかどうかを中身の有無で言う
- 別を装備から移すと、失った印も一緒に外れる。装備でないものに残っていても読みようがない
- `戻った` で取り消せる。見つかることはあるので、片道にはしない

## アイデアの温度

> **いまは伏せてある。**`public/app.js` の `SHOW.temperature` を `true` に戻せば出る。

アイデアには温度（K表記）がある。**273K（0℃）を常温＝基準**とし、
熱を入れてから触らずにいると基準へ向かって冷めていく。

- スライダーで 273K〜373K を設定する。設定すると冷却の起点が今にリセットされる
- 冷却は半減期方式。半減期ぶんの日数が経つごとに、273K からの差が半分になる
  （既定30日。半減期30日・370Kなら 30日後に322K、60日後に297K、180日後に275K）
- 半減期は 設定 → アイデアの冷却 で変えられる。**0 にすると冷めない**
- 温度は保存された値そのものではなく、読むたびに経過時間から計算する。
  つまり冷却のためのバッチ処理は無く、半減期を変えれば過去のアイデアの温度も即座に変わる

熱さは 沸騰（350K〜）／熱い（320K〜）／ぬるい（295K〜）／冷めかけ（276K〜）／凍結（〜275K）で
色とアイコンが変わる。凍結だけ炎ではなく霜の結晶になる。

なお、プロセスを切り出すなどの操作で自動的に熱が戻ることはしていない。
温度を動かすのは明示的な操作だけなので、冷めていることに気づいたら自分で入れ直す。

## プロセスの期日

プロセスには **いつから（開始日）** と **いつまで（期限）** を任意で付けられる。
どちらも `YYYY-MM-DD` のローカル日付で、片方だけでもよい。

- アイデア／ログ詳細のプロセス一覧は**期限順**。期限の近いものから並べ、
  期限の無いものは末尾
- 進行中のものだけ、残り日数をバッジで出す。
  超過（赤）／今日まで（金）／あと3日以内（金）／あとN日（淡色）／N日後に開始
- 日付はカードの「日付を決める」を開けばその場で変えられる。空にすれば外れる
- 期限が開始日より前だと 400 を返す

**大釜にも同じ日付を持たせられる。素材は自分の期限が無ければ大釜の期限を引き継ぐ**
ので、大きなイベントには大釜側に一度だけ日付を振れば足りる。
素材に自分の期限を入れればそちらが優先され、大釜の日付を変えれば引き継いでいる
素材だけが追随する。並び替えもこの実効の期限で行う。

ホームの調合棚と、アイデア／ログ詳細のプロセス一覧も期限順で並ぶ。

## 金庫

**月が終わると、その月のウォレットの余りが金庫に積まれる。**
ホームの試験管の下と、設定から開ける。

- 積まれるのは `使える量 − 消費済み`。**進行中の今週はまだ積まない**
- 使いすぎた月はその分だけ目減りする。マイナスもそのまま反映する
- **初期残高**を設定できる。使い始める前から持っていたぶんを入れておく
- 対象は最初のログがある月から先月まで。ログを取り始める前の月まで遡って
  「使わなかったぶん」を積むと嘘になるため
- 週ごとの内訳（使える量・消費済み・差額）を並べるので、残高の根拠を追える

残高は保存せず、読むたびに週ごとの差額から計算する。使える量を後から直せば
金庫の残高もその場で追従する。

## 週のタイムを表で選ぶ

設定の「週のタイム」は、**曜日×24時間の表を指でなぞって塗る**。
塗ったマスの数がそのまま週のタイム（1マス＝1時間）になる。

- 最初に触ったマスの逆の状態を、指を離すまで塗り続ける。
  塗るときも消すときも同じ操作
- 塗っているあいだ画面がスクロールしないよう、表は `touch-action: none`。
  左の時刻の目盛りは通常どおり触れるので、そこを持てばスクロールできる
- 塗りは168文字の 0/1 として `settings.time_grid` に持つ。
  保存すると `weekly_time` が塗ったマス数から再計算される
- 表がまだ空で、数値で設定した値が残っている場合は、その値を注記に出す。
  塗って保存するまで置き換わらない

週ごとの個別設定（前掲）は数値のままで、表とは別に効く。

## 大釜（プロセスのTODOリスト）

> **いまは伏せてある。**`public/app.js` の `SHOW.cauldron` を `true` に戻せば出る。

ひとつの大きなイベントに必要なプロセスを、**素材**としてまとめて並べる器。
大釜はアイデア／ログにぶら下がり、素材はその大釜に入ったプロセスになる。

- 素材は1行1つのテキストでまとめて投入できる
- 素材が1つ以上あって、**断念を除く全部が完了**すると錬成が終わる。
  逆に完了を取り消したり素材を足したりすると、錬成中に戻る
- 断念した素材は「要らなくなったもの」として必要数から外れる
- 大釜を捨てても素材は消えない。単独のプロセスに戻るだけ

素材も普通のプロセスなので、完了すればログが生成され、リソースの集計も
今までどおり効く。大釜が増やすのは「まとめて並べて、そろったかを見る」という
見え方だけで、リソースの数え方は変えていない。

## 繰り返すプロセス

プロセスは**一回きり**と**繰り返す**に分かれる。アイデア・ログの詳細に並ぶ
プロセス一覧には両方が混ざって出る。種にも生えたほうにも循環の印が付くので、
一覧を見ればどちらか分かる。

繰り返すほうは**周期（日）だけを持つ「種」**で、そこから一回きりのプロセスが生えてくる。
生えたものは自分で立てたものと同じに扱えて、完了も削除もできる。
種と、種から生えたものには**循環の印**（2本の弧が輪になって追いかけ合う印）が付く。

- 無限には作れないので、**今日から90日先まで**を保つ。読むたびに足りないぶんを
  継ぎ足すので、使っている限り先が尽きない。一度に生やすのは60個まで
- **進行中の数は、種を1つと数える。**そこから生えたものは数えない。
  先まで生やしてあるぶんを足すと、増えるのは数字だけで中身は同じになる
- 過去に遡っては生やさない。止まっていた間のぶんは作らず、今日から拾い直す
- **種は完了できない**（409 を返す）。回り続けるものなので、終わるのは止めたとき。
  止めると、まだ手を付けていない先のぶんは引き上げる
- 種は期限を持たない。期限を持つのは生えたほうだけ
- **種は固定費として、可処分から先に引かれる**（前掲）。種の札には、
  毎週いくら持っていくかを出す。周期と見積もりから暗算はできるが、
  頭の中でやらせる理由がない
- 生えたほうは棚にも一覧にも出るが、リソースの数には入らない。
  もう払ったものなので、やっても残量は動かない
- **一覧に出るのは、いちばん近い1回だけ。**先まで生やしてあるので、そのまま並べると
  同じ用事で欄が埋まって、いま見るべきものが押し出される。
  終わった回と止めた回は記録なので全部出す
- **済ませたぶんは、ログのタブの `循環` でまとめて見られる**（`?type=cycle`）。
  これは別（何であるか）ではなく出どころで絞るので、絞り込みの並びでも末尾に置く。
  循環から来たものはいまのところ必ずプロセスの顔なので、
  プロセスの中から「勝手に来たぶん」を抜き出す形になる。
  **ここに並ぶ額は消費済みに入っていない。**固定費として先に引いてあるため（前掲）

`mission` に `repeat_days`（周期）、`repeat_of`（どの種から来たか）、
`repeat_through`（どこまで生やしたか）の3列を足している。

## アストロラーベ

たまっていく情報を、**1枚の盤**として描く画面。天体の位置を読む器具に見立てて、
物事どうしの関わりを角度と輪で出す。

**何と何が関わっているかは、派生したプロセスだけが決める。**
タグのような別の分類軸は持たない。持つと同じことを2通りで表すことになる。

| 盤の要素 | 中身 |
|---|---|
| 節 | アイデア（賢者の石）／ログ（足跡）。輪で描き、中は紙のまま抜く |
| 軌道 | プロセス。親の輪を子の角度まで回ってから、外へ抜ける |
| 崩落 | 断念したプロセス。軌道が点線に落ち、下敷きも暗くなる（過去のぶんだけ。いまは断念を作らない） |
| 行き止まり | 完了していない軌道の先。空の節（掘削中は金、崩落は鈍色） |
| 大釜の節 | 同じ器に入った素材の束。輪の一部を緑にして「3/4」の進み具合を出す |
| 輝き | レガシー。節に金の輪をもう1本回し、軌道に星を添える |
| 灯りの軌道 | いちばん奥の掘削中まで。金の破線。盤ぜんたいで1本だけ |

- 入口はアイデア全部と、プロセス由来ではないログ。**いちばん内側の輪に並べる**
- **中心には何も置かない。**入口どうしは無関係で、線で結ぶと在りもしない
  関わりを描くことになる
- いちばん内側の輪の大きさは葉の数から決める。固定にすると、入口が増えたときに
  内側で節が重なって団子になる
- 大釜は素材ごとに輪を取らない。素材の先にさらに道が続いているものだけ、
  大釜から枝として伸ばす
- 節を押すとその詳細へ飛ぶ。押せるのは絵ではなく節ぜんぶ

### 盤を拡げて繰る

**等倍＝盤ぜんぶが1画面に収まる大きさ**で、そこから4段階まで拡げられる
（1 / 1.5 / 2.25 / 3.4 倍）。等倍より小さくはしない。読めない盤が真ん中に
浮くだけで、得るものがないため。

- 等倍の寸法は枠から毎回出し直す。画面を回しても、等倍が「1画面に収まる
  大きさ」であり続けるようにするため。枠の丈が決まるのは、ページ送りが
  盤の画面だと判じて縦の配分をやり直した後なので、`ResizeObserver` で待つ
- 拡げたぶんは枠の中を**縦にも横にも繰って**見る。素の overflow に任せるので、
  指の慣性もそのまま効く。繰りは枠で止めて、後ろのページ送りへ渡さない
- **拡げる前に見ていた真ん中を、拡げたあとも真ん中に置く。**左上を保つと、
  拡げるたびに盤の中心から離れていく
- 倍率は描き直しをまたいで保つ。期間を変えても同じ盤なので、見ていた寸法で
  出てきたほうが続きを追える
- 手は**左下**に置く。右下は「書き留める」が居る

### 盤に載せる期間

既定は**直近1か月に動いた道だけ**。全部を載せ続けると、何年ぶんかの記録が
いずれ盤を埋めて読めなくなる。古いかどうかはその道でいちばん新しい出来事で
決めるので、入口が古くても最近も掘っているなら現役として残る。

期間を指定すると、当時の盤をそのまま呼び出せる（**エフェメリス**＝ある日付の
天体の位置をまとめた暦表）。`/api/dungeon?since=&until=` で受ける。

### 盤に見せるための決めごと

- **滲みはぼかしで作らない。**同じ中心の輪を段で重ねる。ぼかすとこの画面だけ
  輪郭が溶けて、他と手ざわりが変わってしまう
- 地は紙のまま。夜空に浮かべていた頃の星は、昼の紙に合わないので紙の斑に変えた
- **葉から順に持ち場を配り、親は子の平均に置く。**これで枝が扇に開く
- **軌道は必ず輪に沿わせる。**斜めに直線で結ぶと蜘蛛の巣になる
- 節が乗る輪は、薄い案内線として先に敷いておく
- **盤は縦長の楕円にする。**真円のまま置くと、縦長の画面では上下が余って、
  そのぶん盤が小さく縮む
- **節が居るところだけを切り出して映す。**輪はいちばん深い道の形で決まるので、
  全体を映すと誰も居ない外側の輪ぶんだけ盤が縮む
- 盤の画面は段にも割らず流しもせず、残りの高さを全部盤に渡す

**レガシー**は、ログと**完了した**プロセスにつけられる印で、盤の上で輝く。
進行中のプロセスには付けられない（409 を返す）。輝かせるかどうかだけの
印なので、一覧も絞り込みも持たない。

## MVP の範囲

要件定義の 6.1〜6.5 を実装している。

- ストリーム（種別フィルタ、＋からの追加。＋は全画面に置き、連続で書ける）
- アイデア／ログ詳細（タイトル編集、プロセス追加、紐づくプロセス一覧）
- プロセス（ステータス別フィルタ、元エントリへのリンク、完了／削除）
- ホーム（タイム／ウォレットの試験管、全完了時の残量）
- 設定（週あたりのタイム、月あたりのウォレット）

要件に無いが操作の行き止まりを避けるために足したもの:

- ログ詳細での実消費（タイム／ウォレット）の入力 — 「ログ直接入力で確定」する経路
- 使える量の期間ごとの個別設定（前掲）。要件 6.5 は単一の値だけだが、
  週・月ごとに実態が変わるため既定値からの上書きを持てるようにした
- 繰り返すプロセス、アストロラーベ、レガシー、大釜（前掲）

フェーズ2のうち、アイデアの温度は実装済み（前掲）。
プロセスの「未着手」「保留」、週カレンダーによる時間の
範囲選択はまだ。

## 見た目

**地は紙、差し色は葉の緑。**面を明るく起こし、沈めるのは入力欄などのくぼみだけにする。
実り（金）は宝箱・消費予定・期限・金額にだけ残す。中世ファンタジー寄りの語彙はそのまま。

紙の上では金は文字に使えない（`#a8802a` で白地に 3.4:1）。
**塗りには `--gold`、文字には `--gold-dark`** と使い分けている。

- 絵情報は**ドット絵**。`public/icons.js` に 16x16 のグリッドを文字で持ち、
  横に連続する同色をまとめて `<rect>` に変換する。外部画像は使わない
- **例外は循環の印だけ。**16x16 の枡では、輪と2本の鏃を同時に置くとどちらも
  潰れて団子になる。札に添える大きさ（14〜15px）だと、なおさら矢印だと読めない。
  ここは「循環だ」と一目で分かることが要るので、滑らかな線で描いて白く塗り、
  墨で縁取る。紙の上でも管の上でも白い札として浮く。
  この絵だけ `body` に SVG をそのまま持ち、`shape-rendering` は掛けない
  （掛けると角が立つ）
- **記録の札とプロセスの札は、離れて見ても混ざらないようにする。**
  プロセスは左の縁を太くし（3px→6px）、状態の札に丸底フラスコを添えて、
  何であるかを先に言う。状態しか出していないと、ログの札と見分けが付かない
- **緑はプロセスの側だけで使う。**記録（アイデア・ログ・糧・装備・祭事）の縁は
  土や実りの色にする。糧が薬草色だった頃は、進行中のプロセスと同じ緑だった
- 絵を字に添えるときは、その枠を `flex` にする。絵は塊で描かれるので、
  `text-align` や `display: block` のままだと絵だけが次の行へ落ちる
- アイコンは **アイデア＝賢者の石、ログ（出来事）＝歩いた足跡、予定（プロセス）＝
  満ちた丸底フラスコ、ログの中のプロセス（別を付けていないぶん）＝空の丸底フラスコ**。
  満ちているか空かで、これからの話か、もう済んだ話かを絵でも分ける。
  **アイデアそのものの終わり＝賢者の石を金で磨き直したもの**。アイデアが
  そのままプロセスになったものなので、予定の段階から（フラスコではなく）
  この絵で出す。同じ形のまま色だけ差し替えて特別だと分かるようにする。
  **失った装備＝中身の抜けた兜**。同じ形のまま鋼の面だけ落として、
  持っているかどうかをフラスコと同じ読み方（中身の有無）で言う。
  ほかに設定＝鍵、レガシー＝宝箱、アストロラーベ＝石の門、
  循環＝輪になった2本の弧、金庫＝積んだ金貨、糧＝焼き物、装備＝兜、祭事＝幟、
  **アイテム**（糧と装備のくくり）＝ひもを掛けた包み。宝箱（レガシー）は蓋が
  丸く錠が付いていて、こちらは平らな面にひもの十字。面の色も紙寄りにして分ける。
  **入ってくる向き**＝口を絞った巾着に穴あきの銭（胴を真っ直ぐ落として底を平らに
  切る。丸く描くと16の枡では糧の焼き物と同じ塊に見える）、
  アイデアの温度＝炎（冷めきると霜の結晶）、大釜＝鍋。
  炎は熱さに応じて配色だけ差し替える
- リソースは**2色の試験管**。下から順に、消費済み（薬草色）と消費予定（琥珀・斜線）。
  残量は空のガラスとして残り、使える量を超えると管の縁が赤くなる
- **図案は紙の上で読める濃さに落としてある。**足跡・鍵・紋・炎・霜は単色で輪郭を
  持たないので、暗い地のままの明度だと白地で沈む。平均明度が 168 を超えたものを
  一段ずつ落とした（`iconBody()` の矩形から測れる）
- 書体は **Kaisei Opti**（Font-Kai／SIL OFL 1.1）を同梱して使う。見出しも本文も同じ。
  後ろに積んだシステムの和文書体は、書体が届くまでのあいだと、字が欠けたときの受け皿。
  和文を先頭に置くのは、欧文書体を先に書くと欧文だけ西洋の書体になり、
  和文はシステム任せになって翻訳物のような字面になるため
  （iOS/macOS はヒラギノ、Windows は游書体／BIZ UD、Android は Noto。
  末尾の IPA は Linux 向けの保険で、総称に落ちて中国語の書体が当たるのを防ぐ）
- 書体は**元の TTF をそのままは置かない**。1つ4MB超あるので、WOFF2 に詰め直したうえで
  符号位置で切り分け、`unicode-range` で必要な切れ端だけ落とす。
  ふだんの画面は欧文・記号・かなの約130KBで足りて、漢字は書いた字に当たったぶんだけ来る。
  太さは CSS に出てくる 400 と 700 だけ。`font-display: swap` なので、
  届くまではシステムの明朝で読める。詳しくは `public/fonts/README.md`
- 数値は要件どおり等幅。欧文の等幅を先に書き、仮名・漢字だけ和文書体に落とす

質感は次の4点で作っている。平坦な単色・均一な枠のままだと安く見えるため。
ただし**ぼかしは一切使わない**。にじんだ影となめらかな諧調はドット絵と喧嘩し、
輪郭が溶けて締まらない。

- **すべて平塗り**: 面は単色。立体は `inset 1px 1px 0` の明線と
  `inset -1px -1px 0` の暗線、2本だけで起こす。`box-shadow` にぼかし半径は
  1つも無い（`grep -oE 'box-shadow:[^;]*' | grep -E '[0-9]+px [0-9]+px [1-9]'`
  が空になる状態を保つ）
- **紙の粒**: 全面に SVG の `feTurbulence` をごく薄く敷く。外部画像は使わない。
  白地では乗せると飛ぶので `mix-blend-mode: multiply` で沈める
- **額装**: パネルは薄い縁で締め、内側に葉の細い罫を1本回し、四隅に鉤を置く
- **差し色は安売りしない**: 葉の塗りはフォームの確定動作と現在の選択にだけ使う。
  カードの上で繰り返し出る「完了」は**輪郭だけの葉**（`button.act`）にして、
  塗りつぶしと見分けが付くようにする

文字の読みやすさは実測で確かめている。前景と背景の対比を全画面で測り、
小さい字は 4.5:1、18px 以上は 3:1 を下回らないようにした。
これで葉は `#4a8236`（白抜きの文字で 4.6:1）、補助の文字は `#656b5e` に落ち着いた。
残っているのは送れない側の矢印だけで、これは効かないことを示すためわざと薄い。

押しやすさも同じように測っている。実機を触らずに確かめられる数字なので、
`a / button / input / select / summary` の寸法を全画面で拾い、
**短辺 32px を切るものを残さない**ようにした。

- 高さの下限をまとめて置く。`button` は 40px、入力欄と `summary` は 44px。
  ページ送りの矢印だけは主要な移動手段なので 52×44 と決め打ち
- **見た目を変えたくないところは、判定だけ広げる。**上部のアイコン（36px 角）と
  大釜のチェック（28px 角）は、透明な `::after` を 44px 角で重ねてある。
  上部のアイコンは隙間を 8px 取ってあるので、44px の判定がちょうど接して
  重ならない。隣に取られないことは `elementFromPoint` で確かめている
- 時間の表だけは例外。指で塗る面なので、1マスを的として扱っていない

グラデーションを残しているのは、段で塗ることに意味がある場所だけ。
試験管の液（3段）、温度スライダーの目盛り（5段）、見出しの罫（1pxの線2本）。
いずれもハードストップで、なめらかに混ぜていない。

タブは要件の3つに **アストロラーベ**を加えて4つにした。
つながりを見る画面は他から辿らせるには主役すぎるため。

## 伏せてある機能

多いと感じたものは、消さずに伏せる。表も API も保存済みの値もそのままなので、
旗を戻せば続きから使える。旗は `public/app.js` の頭に1か所だけ置いてある。

```js
const SHOW = { temperature: false, cauldron: false };
```

伏せるときの決めごと：

- **伏せたせいで触れなくなるものを作らない。**大釜に入っているプロセスは、
  伏せている間は器から出して、ふつうのプロセスとして詳細にもアストロラーベにも出す
- **盤では節ごと落とさない。**大釜の節を消すと、その先に続く道まで盤から消える。
  素材を親の軌道として継ぎ直してから節だけ抜く
- 器から継いだ期日は残る。ただし「大釜 → 8/27」ではなく「→ 8/27」と出す。
  出どころの名前を出しても、その画面には出どころが無い

## 画面に説明文を置かない

機能は一度使えば分かるので、操作の手引きは画面に書かない。
書いてあるのは、**使っても気づけないこと**だけ。

- 隠れた特例 — 冷却の「0 で冷めません」。0 を入れない限り出会わない
- 食い違っている時の断り — 週のタイムを数値で入れてある状態で表を開いたとき

これ以外は落とした。空の画面の文言も名詞止めにして、句点まで削っている。
地図の凡例は畳んでおく（記号は地図の中にも文字で出るので、ふだんは要らない）。

## 画面は縦に流す

1画面ぶんずつ横へ送る作りを持っていたが、やめた。

組んである画面ほど枠が境で割れず、段の末尾に白が残る。同じ中身が3ページにも
4ページにもなって、どのページに何が居るのかも覚えていられない。
順に下へ辿れるほうが、探す手数が少なくて済む。

- `html, body` で縦スクロールを止め、シェルは `100dvh` の柱に固定する。
  上端の見出しと下端のタブは動かず、真ん中の `#view` だけが流れる
- **柱の丈は `100vh` を先に置いてから `100dvh` で上書きする。**`dvh` の効かない
  ブラウザ（iOS 16.3 以前の Safari）では宣言ごと落ちて `height: auto` になり、
  中の `#view` が丈を持てない。`html, body` が `overflow: hidden` なので、
  そうなると中身に手が届かなくなる
- **流す枠には `touch-action` を書く**（`#view` は `pan-y`、盤は `pan-x pan-y`。
  どちらも `pinch-zoom` は残す）。書かないと、その指づかいを誰が取るのかの
  判断がブラウザ任せになる。つまむ拡大を取り上げると、字を大きくして読む手が塞がる
- 画面を切り替えたときだけ頭へ戻す。その場の書き換えでは読んでいた所に留まる
- 末尾は「書き留める」の下に隠れるので、そのぶん下に余白を置く

**盤だけは流さない。**残りの高さを全部盤に渡し、盤は枠の中で自分で繰る（前掲）。
外側まで流れると、どちらが動いているのか分からなくなる。

### 週の表は「塗る」を入れている間だけ指を取る

塗るための表は画面の半分以上を覆う。いつでも指を取っていると流す場所が無くなり、
そのうえ掴んだつもりで週が塗り変わってしまう。

`塗る` を押している間だけ `touch-action: none` にして、ふだんは触っても
何も起きないようにしてある。押した1枡は捕捉より先に塗る。
捕捉に失敗する指でも、押した所だけは必ず変わるように。
